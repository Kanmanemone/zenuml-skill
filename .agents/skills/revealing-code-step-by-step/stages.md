# 정제 단계 정의

독자의 인지 부담이 한꺼번에 몰리지 않도록, 한 장면에 한 가지씩 더한다. 먼저 노드의 모든 단계를 번호 붙은 자리표시자로 보이고(숲), 그다음 한 겹씩 원본으로 펼친다(나무). 단계 목록의 정본은 이 파일뿐이다.

`## 별명`마다 `표현`, `원본과 같아지는 것`, `아직 드러나지 않은 것`은 필수다. 표현은 `prose` → `outline` → `unfold` → `source` 순서로 하나씩이며, 각 장면은 `scripts/stages.py`가 만든다. 별명은 바꿔도 되고, 보일지는 `settings.jsonc`의 `stages`에서 정한다. 마지막 원본은 항상 보인다.

## 사용 상황

- 표현: prose
- 원본과 같아지는 것: 구조 뷰만으로 확인되는 사용 상황
- 아직 드러나지 않은 것: 코드, 하는 일의 목록, 협력자, 실제 API

원본을 모르는 서브에이전트가 1~2문장 한 문단으로 쓴다. 노드의 책임 문장은 상자 위 책임 줄이 보이므로 되풀이하지 않고, 책임 줄에 없는 상황(누가·언제 필요로 하는지)만 쓴다. 근거가 없으면 명시되지 않았다고 쓴다.

## 윤곽

- 표현: outline
- 원본과 같아지는 것: 노드의 선언 머리(노드 자신의 주석·어노테이션·수식어·종류·상속), 노드의 모든 펼치기 단계
- 아직 드러나지 않은 것: 멤버와 본문, 아직 쓰이지 않은 매개변수

본문에는 루트 스코프의 묶음마다 `⟨번호. 문장⟩` 한 줄을 원본 자리에 두고, 그 안에 든 뒤 단계들을 바로 아래에 들여 써서 함께 보인다. 번호는 펼치는 순서다. 쓰이지 않은 매개변수는 `...`으로 접는다.

## 펼치기

- 표현: unfold
- 원본과 같아지는 것: 이번 묶음의 원본 한 겹(그 주석, 함께 바로 보이는 자식, 처음 쓰이는 비공개 멤버·상태·매개변수)
- 아직 드러나지 않은 것: 이번 묶음 안에 따로 남긴 묶음들, 뒤 단계들

노드마다 따로 남긴 묶음 수만큼 반복한다. 원본은 기계적으로 스코프 트리로 나뉜다: 블록 안의 문장, 여러 줄 인자 목록의 인자(이어지는 한 줄 인자는 하나), 여러 줄 체인의 고리. 자식 하나뿐인 층은 합친다. 모델은 스코프마다 목적 문장 하나와 자식 묶음(함께 보임 하나, 따로 남김 4개 이하)을 정한다. 펼치는 순서는 감싸는 자리가 먼저, 같은 자리 안에서는 원본에서 위에 있는 것이 먼저, 한 묶음을 펼치면 그 안을 다 펼친 뒤 다음으로 간다. 한 장면에는 한 겹만 열린다 — 따로 남긴 안쪽 묶음은 그 장면에서 자리표시자로 남는다.

## 원본

- 표현: source
- 원본과 같아지는 것: 원본 범위의 모든 글자·주석·빈 줄·들여쓰기
- 아직 드러나지 않은 것: 없음

마지막으로 보이는 코드 장면이 이미 원본이면 따로 보이지 않는다(펼치기를 모두 보이면 늘 그렇다).

## 단계를 고칠 때 (토큰을 아끼는 원칙)

단계를 더하거나 바꾸거나 뺄 때는 다음을 지킨다.

1. 원본이나 구조 뷰로 정해지는 일(무엇을 어느 장면에 보일지, 순서, 빈 줄, 생략, 검증, 렌더링)은 모두 `stages.py`가 한다. 모델은 장면 코드를 쓰지 않는다.
2. 모델은 뜻을 정해야 하는 것만, 작은 구조화 입력 하나로 한 번에 쓴다(지금은 `work/outline.json`의 스코프별 목적 문장과 묶음). 늘 뻔한 판단(예: 자식 하나뿐인 층)은 구조에서 없애고 모델에게 묻지 않는다.
3. 원본은 모델에게 한 번만, 각 줄이 한 번씩만 보인다. 안쪽 스코프는 식별자 하나로 접어 같은 줄이 부모와 자식에 겹쳐 나오지 않게 한다. 단계마다 다시 출력하지 않는다. 프롬프트에서 되풀이되는 입력은 뺀다(예: 1단계 프롬프트의 Mermaid `click` 줄). 원본이 크면 비용이 그만큼 드는 것은 그대로 둔다 — 없애는 것은 구조적 낭비다.
4. 모델 입력이 틀리면 스크립트가 형식·덮기·묶음 수·문장 규칙을 기계적으로 검사해 거부하고, 틀린 스코프마다 한 줄씩 알린다. 모델은 그 스코프만 고친다.
5. 바꾸기 전후로 같은 구조 뷰 예제에서 모델이 읽고 쓰는 글자 수를 재서 비교한다. 이 수치는 판단 근거이고 합격 기준이 아니다.

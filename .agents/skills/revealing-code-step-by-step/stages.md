# 정제 단계 정의

독자의 인지 부담이 한꺼번에 몰리지 않도록, 한 장면에 한 가지씩 더한다. 먼저 노드가 하는 일의 목록(숲)을 보이고, 그다음 한 가지씩 원본으로 펼친다(나무). 단계 목록의 정본은 이 파일뿐이다.

`## 별명`마다 `표현`, `원본과 같아지는 것`, `아직 드러나지 않은 것`은 필수다. 표현은 `prose` → `outline` → `unfold` → `source` 순서로 하나씩이며, 각 장면은 `scripts/stages.py`가 만든다. 별명은 바꿔도 되고, 보일지는 `settings.jsonc`의 `stages`에서 정한다. 마지막 원본은 항상 보인다.

## 사용 상황

- 표현: prose
- 원본과 같아지는 것: 구조 뷰만으로 확인되는 사용 상황
- 아직 드러나지 않은 것: 코드, 하는 일의 목록, 협력자, 실제 API

원본을 모르는 서브에이전트가 1~2문장 한 문단으로 쓴다. 노드의 책임 문장은 상자 위 책임 줄이 보이므로 되풀이하지 않고, 책임 줄에 없는 상황(누가·언제 필요로 하는지)만 쓴다. 근거가 없으면 명시되지 않았다고 쓴다.

## 윤곽

- 표현: outline
- 원본과 같아지는 것: 노드의 선언 머리(노드 자신의 주석·어노테이션·수식어·종류·상속), 노드가 하는 일의 목록
- 아직 드러나지 않은 것: 멤버와 본문, 아직 쓰이지 않은 매개변수

본문에는 펼치기 단위마다 `⟨자리표시자⟩` 한 줄을 원본 순서로 둔다. 쓰이지 않은 매개변수는 `...`으로 접는다.

## 펼치기

- 표현: unfold
- 원본과 같아지는 것: 이번 펼치기 단위의 원본 전부(그 멤버의 주석, 붙은 비공개 멤버·상태, 그 단위가 처음 쓰는 매개변수)
- 아직 드러나지 않은 것: 다음 단위들, 이번 단위 안에서 접은 결

노드마다 단위 수만큼 반복한다. 단위는 원본에서 기계적으로 정한다: 공개 멤버(함수는 본문의 최상위 문장) 하나, 원본 순서. 비공개 멤버·한 줄 가변 상태·매개변수는 처음 쓰는 단위에 붙고, 본문 없는 같은 종류 선언이 이어지면 묶고, 4개를 넘으면 이웃한 두 단위 중 줄 수 합이 가장 작은 쌍부터 합친다. 핵심이 아닌 결은 `⟨설명⟩` 한 줄로 접을 수 있다.

## 원본

- 표현: source
- 원본과 같아지는 것: 원본 범위의 모든 글자·주석·빈 줄·들여쓰기(접은 결 포함)
- 아직 드러나지 않은 것: 없음

접은 결이 없어 마지막 펼치기가 이미 원본이면 따로 보이지 않는다.

## 단계를 고칠 때 (토큰을 아끼는 원칙)

단계를 더하거나 바꾸거나 뺄 때는 다음을 지킨다.

1. 원본이나 구조 뷰로 정해지는 일(무엇을 어느 장면에 보일지, 순서, 빈 줄, 생략, 검증, 렌더링)은 모두 `stages.py`가 한다. 모델은 장면 코드를 쓰지 않는다.
2. 모델은 뜻을 정해야 하는 것만, 작은 구조화 입력 하나로 한 번에 쓴다(지금은 `work/outline.json`의 자리표시자와 접기).
3. 원본은 모델에게 한 번만 보인다. 단계마다 다시 출력하지 않는다. 프롬프트에서 되풀이되는 입력은 뺀다(예: 1단계 프롬프트의 Mermaid `click` 줄).
4. 모델 입력이 틀리면 스크립트가 개수·형식·책임 줄과의 중복을 기계적으로 검사해 거부한다.
5. 바꾸기 전후로 북마크 예제에서 모델이 읽고 쓰는 글자 수를 재서 비교한다.

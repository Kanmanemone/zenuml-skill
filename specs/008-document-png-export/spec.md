# Feature Specification: 문서 전체를 PNG 이미지로 내보내기

**Feature Branch**: `008-document-png-export`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "exporting-markdown-diagrams에서 문서 전체(scope=document)를 PDF뿐 아니라 이미지 파일(PNG, SVG)로도 변환할 수 있게 한다. 지금은 문서 전체 변환이 PDF만 지원되어, 문서 전체를 고르면 형식이 항상 PDF로 고정된다. 설정의 defaults.format·defaults.scope와도 맞물려야 한다(예: scope=document + format=png)."

## Clarifications

### Session 2026-11-13

- Q: 문서 전체를 이미지로 만들 때 페이지 구성은 어떻게 하는가? → A: PDF와 같은 선택을 쓴다. "1페이지 단일"은 세로로 긴 이미지 한 장, "표준 인쇄 규격"은 인쇄 용지 크기로 나눈 이미지 여러 장이다. 기존 페이지 구성 질문과 `defaults.pdfLayout` 설정을 그대로 재사용한다.
- Q: 문서 전체 SVG도 지원하는가? → A: 지원하지 않는다. 문서의 글·표·목록을 SVG에 담으려면 HTML을 SVG 안에 통째로 넣는 방식밖에 없어, 일부 이미지 뷰어·편집기에서 글자가 보이지 않을 수 있기 때문이다. 문서 전체는 PDF와 PNG만 지원하며, SVG를 요청하면 지원하지 않음을 알리고 PDF·PNG 중에서 고르게 한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 문서 전체를 PNG로 받기 (Priority: P1)

사용자가 마크다운 문서 전체를 PNG로 변환해 달라고 하면, 스킬은 문서의 글·표·목록·다이어그램을 모두 담은 PNG를 만든다. 페이지 구성이 "1페이지 단일"이면 문서 전체가 세로로 긴 이미지 한 장에, "표준 인쇄 규격"이면 인쇄 용지 크기로 나뉜 이미지 여러 장에 담긴다. 모양(글꼴, 여백, 다이어그램 배치)은 같은 문서의 PDF와 같다.

**Why this priority**: 사용자가 요청한 핵심 기능이다 — 메신저·이슈 트래커처럼 PDF보다 이미지가 편한 곳에 문서를 통째로 붙여 넣을 수 있게 한다.

**Independent Test**: 다이어그램과 접은 글 상자가 있는 마크다운 문서를 두 페이지 구성으로 각각 PNG 변환해, 결과 이미지 장수·내용·모양이 같은 문서의 PDF와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다이어그램이 있는 마크다운 문서, **When** 사용자가 "문서 전체를 PNG로, 한 페이지로" 변환을 요청하면, **Then** 원본 옆 산출물 위치에 문서 전체를 담은 PNG 한 장이 만들어지고, 글·표·다이어그램이 모두 보인다.
2. **Given** 같은 문서, **When** 페이지 구성을 "표준 인쇄 규격"으로 요청하면, **Then** 인쇄 용지 크기로 나뉜 PNG가 페이지 순서대로 번호가 붙어 여러 장 만들어지고, 장수가 같은 문서를 같은 구성으로 만든 PDF의 페이지 수와 같다.
3. **Given** 접은 글 상자가 있는 문서, **When** PNG로 변환하면, **Then** 상자 안 내용이 펼쳐진 상태로 이미지에 담긴다.
4. **Given** PNG 해상도 배율 설정, **When** 문서 전체를 PNG로 변환하면, **Then** 다이어그램만 변환할 때와 같은 배율이 적용된다.

---

### User Story 2 - 형식·범위 선택과 설정이 문서 전체 PNG와 맞물리기 (Priority: P2)

문서 전체를 고르면 형식이 PDF로 자동 고정되던 동작이 바뀐다. 문서 전체일 때 형식이 정해지지 않았으면 PDF와 PNG 중에서 고르며(질문을 켜 두면 질문, 끄면 설정 기본값), 설정의 기본 형식이 PNG이고 기본 범위가 문서 전체이면 묻지 않고(질문을 끈 경우) 문서 전체 PNG를 만든다.

**Why this priority**: 사용자가 요청한 설정 연동이다. US1이 있어야 의미가 있다.

**Independent Test**: 질문 켬/끔, 기본 형식(none/png/svg/pdf), 기본 범위(document) 조합을 바꿔 가며 "이거 변환해줘"를 요청해, 묻는 질문과 결과 형식이 아래 시나리오대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 범위가 문서 전체로 정해지고 형식이 정해지지 않은 요청, 질문이 켜진 설정, **When** 스킬이 형식을 물으면, **Then** 선택지는 PDF와 PNG 두 개이고(SVG 없음), 기본 형식 설정과 같은 선택지에 " (기본값)"이 붙는다.
2. **Given** 질문이 꺼져 있고 기본 범위가 문서 전체, 기본 형식이 PNG, 기본 페이지 구성이 1페이지 단일인 설정, **When** 사용자가 "이거 변환해줘"라고 하면, **Then** 아무것도 묻지 않고 문서 전체를 PNG 한 장으로 만든다.
3. **Given** 범위가 문서 전체인데 사용자가 SVG를 요청함, **When** 스킬이 처리하면, **Then** 문서 전체 SVG는 지원하지 않는다고 알리고 PDF와 PNG 중에서 고르게 한다.
4. **Given** 질문이 꺼져 있고 기본 형식이 SVG, 범위가 문서 전체로 정해진 요청, **When** 스킬이 형식을 채우려 하면, **Then** SVG는 문서 전체에 쓸 수 없으므로 형식을 채우지 못한 것으로 보고 PDF·PNG 중에서 묻는다.
5. **Given** 범위가 문서 전체이고 형식이 PNG로 정해졌으며 페이지 구성이 정해지지 않은 요청, **When** 스킬이 진행하면, **Then** PDF일 때와 같은 페이지 구성 질문(또는 질문을 끈 경우 기본 페이지 구성)이 적용된다.

---

### Edge Cases

- 다이어그램이 하나도 없는 문서도 문서 전체 PNG로 변환할 수 있다(다이어그램만 변환과 달리 "다이어그램 없음" 실패가 아니다).
- 문서가 너무 길어 1페이지 단일 PNG를 만들 수 없으면(이미지 크기 한계 등), 스킬은 실패를 그대로 알리며 다른 형식이나 다른 페이지 구성으로 몰래 바꾸지 않는다.
- 사용자가 출력 파일 이름을 직접 지정하면 1페이지 단일은 그 이름을 쓰고, 표준 인쇄 규격은 그 이름 뒤에 페이지 번호를 붙인다.
- 문서 전체 PDF의 기존 동작(형식이 PDF일 때의 결과, 접은 글 펼침, 산출물 위치)은 바뀌지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 스킬은 문서 전체를 PNG로 변환할 수 있어야 한다. 결과는 문서의 모든 글·표·목록·코드 블록·다이어그램을 담아야 한다.
- **FR-002**: 페이지 구성이 "1페이지 단일"이면 문서 전체를 세로로 긴 PNG 한 장에, "표준 인쇄 규격"이면 같은 구성의 PDF와 같은 페이지 나눔으로 페이지마다 PNG 한 장씩 담아야 한다. 여러 장일 때 파일 이름에 1부터 시작하는 페이지 번호를 붙인다.
- **FR-003**: 문서 전체 PNG의 모양(글꼴, 글자 크기, 줄 간격, 여백, 다이어그램 크기·배치)은 같은 문서·같은 페이지 구성의 PDF와 같아야 한다.
- **FR-004**: 문서 전체 PNG는 접은 글 상자를 모두 펼친 상태로 담아야 하며, 원본 파일은 바뀌지 않는다(007 FR-015와 같은 고정 동작).
- **FR-005**: 문서 전체 PNG에도 PNG 해상도 배율 설정(`png.scale`)과 산출물 위치 설정(`output.directory`)이 다이어그램 변환과 같은 방식으로 적용돼야 한다.
- **FR-006**: 범위가 문서 전체일 때 형식은 PDF 또는 PNG여야 한다. 범위가 문서 전체로 정해지면 형식이 PDF로 자동 고정되던 기존 규칙은 없어지고, 형식이 정해지지 않았으면 PDF와 PNG 중에서 정한다.
- **FR-007**: 범위가 문서 전체일 때 형식 질문의 선택지는 PDF와 PNG뿐이어야 하며, 질문이 켜져 있으면 `defaults.format`과 같은 선택지에 " (기본값)"을 붙인다(007 FR-013b). `defaults.format`이 `svg`이거나 `none`이면 어느 선택지에도 붙이지 않는다.
- **FR-008**: 질문이 꺼져 있으면, 범위가 문서 전체일 때 `defaults.format`이 `pdf`나 `png`이면 그 형식으로 채우고, `svg`나 `none`이면 채우지 못한 것으로 보고 PDF·PNG 형식 질문만 한다.
- **FR-009**: 범위가 문서 전체인데 요청이 SVG를 지정하면, 스킬은 문서 전체 SVG를 지원하지 않는다고 알리고 PDF·PNG 형식 질문을 한다 — SVG를 다른 형식으로 몰래 바꾸지 않는다.
- **FR-010**: 범위가 문서 전체이고 형식이 PDF 또는 PNG로 정해지면, 페이지 구성은 기존 규칙(요청 → 설정 기본값 `defaults.pdfLayout` → 질문)으로 정한다. 페이지 구성 질문과 설정은 PNG에도 같은 의미로 적용된다.
- **FR-011**: 변환은 기존처럼 번들 스크립트가 결정적으로 수행해야 하며 LLM 판단에 의존해서는 안 된다(004 원칙). 같은 입력·설정으로 반복 변환하면 같은 장수·같은 크기의 PNG가 나와야 한다.
- **FR-012**: 변환에 실패하면 스킬은 스크립트가 보고한 실패를 그대로 알려야 하며, 다른 형식·다른 페이지 구성으로 대신 만들어서는 안 된다.

### Key Entities *(include if feature involves data)*

- **문서 전체 PNG**: 원본 마크다운 하나에서 만든 PNG 묶음. 1페이지 단일이면 한 장, 표준 인쇄 규격이면 페이지 수만큼. 파일 이름은 원본 이름(+ 페이지 번호).
- **형식·범위 조합**: 다이어그램만 → SVG/PNG/PDF, 문서 전체 → PDF/PNG.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대표 문서들에서 문서 전체 PNG에 원본의 글·다이어그램·접은 글 내용이 빠지는 비율이 0%다.
- **SC-002**: 표준 인쇄 규격으로 만든 문서 전체 PNG의 장수가 같은 문서·같은 구성의 PDF 페이지 수와 같은 비율이 100%다.
- **SC-003**: 같은 입력·설정으로 두 번 변환했을 때 PNG 장수와 픽셀 크기가 같은 비율이 100%다.
- **SC-004**: 범위가 문서 전체일 때 형식 질문에 SVG가 선택지로 나오거나, SVG 요청이 다른 형식으로 몰래 바뀌는 비율이 0%다.
- **SC-005**: 질문을 끄고 기본 범위 문서 전체·기본 형식 PNG·기본 페이지 구성을 정해 둔 상태에서 "이거 변환해줘"에 질문 없이 문서 전체 PNG가 만들어지는 비율이 100%다.
- **SC-006**: 이 기능 도입 전과 같은 요청(문서 전체 PDF, 다이어그램만 변환)의 결과가 달라지는 비율이 0%다.

## Assumptions

- **PNG만 지원하는 이유**: 문서 전체 SVG는 HTML을 SVG 안에 통째로 넣는 방식밖에 없어 뷰어 호환성이 낮으므로 이번 범위에서 제외한다(Clarifications).
- **설정 키 이름**: 페이지 구성 기본값 키 `defaults.pdfLayout`은 이름을 바꾸지 않고 PNG에도 적용한다 — 이름을 바꾸면 사용자가 이미 고친 설정 파일이 알 수 없는 키가 되기 때문이다. 옵션 설명 주석만 "PDF·PNG 공통"으로 고친다.
- **모양 기준**: 문서 전체 PNG는 문서 전체 PDF와 같은 렌더링(같은 글꼴·스타일)을 쓰므로, PDF에 이미 적용된 VS Code 미리보기 글꼴 일치와 다이어그램 잘림 방지가 그대로 적용된다.
- **이미지 크기 한계**: 매우 긴 문서의 1페이지 단일 PNG는 브라우저 렌더링 한계로 만들 수 없을 수 있다. 이 경우 실패로 알리며, 한계를 피하는 분할·축소 같은 자동 대처는 이번 범위가 아니다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 다이어그램을 이미지로 export하기 (Priority: P1)

마크다운 파일 안에 있는 다이어그램(이 저장소의 zenuml 플레이버 시퀀스 다이어그램이나 일반 Mermaid flowchart)을 SVG 또는 PNG 파일로 받고 싶다. 요청에 출력 형식을 명시했으면 그 형식으로, 명시하지 않았으면 확인 질문을 거쳐 바로 변환된 파일을 받는다.

**Why this priority**: 평가 단계(`research.md`)에서 확인된 가장 반복적인 아픈 지점 — 지금까지 매번 에이전트에게 추론시켜 처리해온, 가장 기본적인 변환 시나리오다. 이것 하나만 있어도 "다이어그램을 이미지로 뽑아달라"는 반복 요청을 완전히 대체할 수 있는 최소 가치 단위다.

**Independent Test**: 다이어그램이 포함된 마크다운 파일 하나를 대상으로, "이 다이어그램 png로 뽑아줘"처럼 형식이 명시된 요청과 "이 다이어그램 이미지로 만들어줘"처럼 형식이 명시되지 않은 요청을 각각 실행해, 전자는 즉시, 후자는 확인 질문 후 SVG/PNG 파일이 생성되는 것으로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 다이어그램이 포함된 마크다운 파일과 "png로 변환해줘"라는 요청, **When** 스킬이 실행되면, **Then** 확인 질문 없이 바로 그 다이어그램의 PNG 파일이 생성된다.
2. **Given** 같은 파일과 형식이 명시되지 않은 "이 다이어그램 이미지로 만들어줘"라는 요청, **When** 스킬이 실행되면, **Then** 출력 형식(SVG/PNG/PDF)을 묻는 확인 질문이 먼저 제시되고, 사용자가 선택한 형식으로 변환된다.
3. **Given** `defaultRenderer`가 명시적으로 지정된 다이어그램 소스, **When** 변환이 수행되면, **Then** 결과물은 그 지정된 렌더러로 그려진 것과 일치하며 기본 렌더러로 조용히 바뀌지 않는다.

### User Story 2 - 문서 전체를 PDF로 export하기 (Priority: P2)

다이어그램이 포함된 마크다운 파일 전체를, 포함된 다이어그램의 텍스트까지 선택·복사할 수 있는 PDF 문서로 받고 싶다.

**Why this priority**: 다이어그램 단독 export(User Story 1)보다 더 무거운 시나리오지만(문서 전체와 다이어그램을 함께 다뤄야 함), 사용자가 명시적으로 요구한 두 번째 변환 축이며 User Story 1의 변환 능력 위에 자연스럽게 쌓이는 확장이다.

**Independent Test**: 다이어그램이 포함된 마크다운 파일 하나를 대상으로 "이 문서 pdf로 만들어줘"를 실행해, 생성된 PDF를 열었을 때 다이어그램이 포함돼 있고 그 안의 텍스트를 PDF 뷰어에서 드래그해 선택·복사할 수 있는 것으로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 다이어그램이 포함된 마크다운 파일과 "문서 전체를 pdf로 만들어줘"라는, 형식·범위가 모두 명시된 요청, **When** 스킬이 실행되면, **Then** 확인 질문 없이 바로 PDF 파일이 생성된다.
2. **Given** 같은 파일과 형식·범위가 모두 명시되지 않은 "이거 변환해줘"라는 요청, **When** 스킬이 실행되면, **Then** 변환 범위(다이어그램만/문서 전체)와 출력 형식(SVG/PNG/PDF)을 함께 묻는 확인 질문이 한 번의 상호작용으로 제시된다.
3. **Given** 생성된 PDF, **When** PDF 뷰어에서 다이어그램 안의 텍스트를 드래그하면, **Then** 그 텍스트가 선택되고 복사된다(래스터 이미지로 삽입되지 않았음을 의미).

---

### Edge Cases

- 대상 문서에 다이어그램이 여러 개 있고 범위가 "다이어그램만"으로 정해졌는데 사용자가 특정 다이어그램을 지목하지 않았다면 어떤 다이어그램(들)을 변환하는가? → 문서에 등장하는 모든 다이어그램을 각각 개별 파일로 변환한다(Assumptions 참고).
- 대상 문서에 변환할 다이어그램이 하나도 없는데 범위가 "다이어그램만"으로 정해지면 어떻게 되는가? → 변환할 다이어그램이 없다고 안내하고 중단한다.
- 요청된 파일이 존재하지 않거나 마크다운 파일이 아니면 어떻게 되는가? → 파일을 찾을 수 없거나 지원하지 않는 형식이라고 안내하고 중단한다.
- 다이어그램 소스가 이번 범위에서 지원하는 두 유형(zenuml 플레이버, 일반 Mermaid) 어느 쪽도 아니면 어떻게 되는가? → 렌더링 도구가 보고하는 오류를 그대로 사용자에게 전달한다 — 스킬이 임의로 해석하거나 다른 문법으로 바꿔 시도하지 않는다.
- 변환에 필요한 도구/런타임(예: 헤드리스 브라우저 다운로드)이 없거나 실행이 실패하면 어떻게 되는가? → 실패를 명확히 안내한다 — LLM 추론으로 대신 처리하는 방식으로 조용히 전환하지 않는다(FR-005 위반 방지).
- 산출물을 모을 전용 하위 디렉토리(`exports/`)가 아직 없으면 어떻게 되는가? → 변환 전에 자동으로 생성한다(사용자가 미리 만들어 둘 필요가 없다).
- 원본 마크다운 파일이 있는 디렉토리에 쓰기 권한이 없으면 어떻게 되는가? → 디렉토리 생성/쓰기 실패를 있는 그대로 사용자에게 안내하고 중단한다(조용히 다른 위치로 대체하지 않는다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 스킬은 사용자의 요청에 출력 형식(SVG/PNG/PDF)이 명시돼 있으면 그대로 사용해야 하며, 명시돼 있지 않으면 변환을 시작하기 전에 확인 질문으로 형식을 선택받아야 한다.
- **FR-002**: 스킬은 사용자의 요청에 변환 범위(다이어그램만 vs 문서 전체)가 명시돼 있으면 그대로 사용해야 하며, 명시돼 있지 않으면 변환을 시작하기 전에 확인 질문으로 범위를 선택받아야 한다.
- **FR-003**: 출력 형식과 변환 범위가 모두 명시되지 않은 요청에서는, 스킬은 이 둘을 묻는 질문 두 개를 하나의 확인 상호작용으로 함께 제시해야 한다. 둘 중 하나만 불분명하면 그 하나만 물어야 한다.
- **FR-004**: 스킬은 변환 대상 다이어그램/문서 소스를 있는 그대로 렌더러에 전달해야 하며, 소스 안에 명시된 렌더러 지정(예: `defaultRenderer`)이나 다른 설정을 임의로 제거·대체하거나 기본값으로 되돌려서는 안 된다.
- **FR-005**: 스킬은 변환(다이어그램/문서를 목표 형식으로 바꾸는 처리) 자체를 LLM 추론이 아니라 결정적인 스크립트/도구 실행으로 수행해야 한다.
- **FR-006**: 스킬은 이 저장소가 실제로 만들어내는 두 다이어그램 유형(zenuml 플레이버 시퀀스 다이어그램, 일반 Mermaid flowchart) 모두를 성공적으로 변환할 수 있어야 한다.
- **FR-007**: 변환 범위가 "문서 전체"이고 출력 형식이 PDF일 때, 문서에 포함된 다이어그램은 래스터 이미지가 아니라 벡터(SVG) 형태로 PDF에 삽입되어, 다이어그램 안의 텍스트가 PDF 뷰어에서 선택·복사 가능해야 한다.
- **FR-008**: 변환 범위가 "다이어그램만"일 때는 대상 다이어그램(들)만 선택된 형식으로 변환해야 하며, 문서의 나머지 내용은 건드리지 않는다.
- **FR-009**: 스킬이 만들어내는 모든 산출물 파일(다이어그램 단독 SVG/PNG, 다이어그램 단독 PDF, 문서 전체 PDF)은 원본 마크다운 파일과 같은 디렉토리가 아니라, 그 디렉토리 바로 아래의 전용 하위 디렉토리(`exports/`)에 생성되어야 한다.
- **FR-010**: 전용 하위 디렉토리가 존재하지 않으면 변환 시점에 자동으로 생성해야 한다.
- **FR-011**: 산출물 파일명 규칙(베이스 이름, `-1`/`-2` 같은 다이어그램 번호 매김 등)은 이 디렉토리 규칙과 무관하게 유지되어야 한다 — 바뀌는 것은 그 파일이 위치하는 디렉토리뿐이다.
- **FR-012**: 원본 마크다운 파일이 있는 디렉토리 하나에 여러 파일이 있고 각각 변환되는 경우, 그 산출물들은 모두 같은 하나의 전용 하위 디렉토리를 공유해야 한다(원본 파일마다 별도의 하위 디렉토리를 새로 만들지 않는다).
- **FR-013**: PNG로 변환할 때는 다이어그램의 가로·세로 픽셀 크기를 고정값으로 미리 정하지 않고, 고정된 해상도 배율(DPI에 해당하는 값)을 기준으로 다이어그램의 실제 레이아웃 크기에 맞춰 픽셀 수가 정해져야 한다 — 큰 다이어그램일수록 더 큰 PNG가 나오되, 텍스트와 선이 흐릿해지지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **변환 요청**: 사용자의 요청에서 판단되거나 확인 질문으로 결정된 두 값을 담는다 — 변환 범위(다이어그램만 | 문서 전체)와 출력 형식(SVG | PNG | PDF).
- **다이어그램 소스**: 마크다운 파일 안에 있는, 변환 대상이 되는 다이어그램의 원본 코드(예: Mermaid/ZenUML 코드 펜스). 렌더러 지정을 포함해 수정 없이 그대로 렌더러에 전달된다.
- **변환 산출물**: 완료된 변환 결과 파일 — SVG/PNG(다이어그램 단독) 또는 PDF(다이어그램 단독 또는 문서 전체; 문서 전체인 경우 포함된 다이어그램이 벡터로 삽입됨). 원본 마크다운이 있는 디렉토리 바로 아래의 전용 산출물 디렉토리에 생성된다.
- **전용 산출물 디렉토리**: 원본 마크다운 파일이 위치한 디렉토리 바로 아래에 있는, 변환 산출물만을 모아두는 하위 디렉토리(`exports/`).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 출력 형식과 변환 범위가 이미 요청에 명시된 경우, 불필요한 확인 질문 없이 바로 변환이 완료되는 비율이 100%다.
- **SC-002**: 출력 형식 또는 변환 범위 중 하나 이상이 불분명한 요청에서, 진행 전에 정확히 그 불분명한 항목(들)만 확인 질문으로 묻는 비율이 100%다(형식·범위가 모두 불분명하면 질문 두 개가 하나의 상호작용으로 함께 제시됨).
- **SC-003**: 변환된 결과물에 원본과 다르게 재해석되거나 새로 생성된 내용이 섞이는 비율이 0%다(변환 자체가 결정적 스크립트/도구 실행만으로 이뤄짐을 의미).
- **SC-004**: "문서 전체"를 PDF로 변환한 결과물에서, 포함된 다이어그램의 텍스트를 PDF 뷰어에서 선택·복사할 수 있는 비율이 100%다.
- **SC-005**: 다이어그램 소스에 렌더러가 명시적으로 지정된 경우, 최종 변환 결과가 그 지정된 렌더러로 그려진 것과 일치하는 비율이 100%이고, 기본 렌더러로 조용히 대체되는 비율이 0%다.
- **SC-006**: 이 저장소가 실제로 만들어내는 두 다이어그램 유형(zenuml 플레이버, 일반 Mermaid flowchart) 각각의 변환 성공률이 100%다.
- **SC-007**: 다이어그램 단독 변환과 문서 전체 PDF 변환 모두에서, 산출물이 원본 마크다운과 같은 디렉토리가 아니라 전용 하위 디렉토리(`exports/`) 안에 생성되는 비율이 100%다.
- **SC-008**: 전용 하위 디렉토리가 미리 존재하지 않는 상태에서 변환을 실행해도 실패 없이 그 디렉토리가 자동으로 만들어지는 비율이 100%다.
- **SC-009**: PNG로 변환된 다이어그램을 실제 크기로 열었을 때, 텍스트와 선이 흐릿하거나 계단현상 없이 선명하게 보이는 비율이 100%다.

## Assumptions

- PNG 변환은 별도의 벡터→래스터 재변환 단계를 거치지 않고, 렌더링 도구가 직접 만들어내는 PNG 출력을 그대로 사용하는 것을 기본값으로 한다 — 조사 결과, 널리 쓰이는 다이어그램 렌더링 도구는 하나의 렌더링 결과를 SVG(직렬화)와 PNG(스크린샷) 두 가지 방식으로 각각 얻을 뿐 서로 다른 파이프라인을 거치지 않는다. 별도의 SVG→PNG 재변환 단계를 추가하면 이점 없이 위험(다른 래스터라이저로 인한 폰트·크기 차이)과 처리 단계만 늘어난다. 구체적인 도구 선택은 계획 단계에서 다룬다.
- 문서에 다이어그램이 여러 개 있고 범위가 "다이어그램만"으로 정해졌는데 사용자가 특정 다이어그램을 지목하지 않았다면, 문서에 등장하는 모든 다이어그램을 각각 개별 파일로 변환하는 것을 기본값으로 한다.
- "문서 전체"를 PDF로 변환할 때 다이어그램을 벡터로 삽입하는 정확한 파이프라인(예: 렌더링된 결과를 그대로 PDF로 인쇄하는 방식 등)은 계획 단계에서 구체화한다 — 이 스펙은 "텍스트가 선택 가능한 벡터로 삽입돼야 한다"는 결과만 요구한다.
- 대상 실행 환경(필요한 런타임, 헤드리스 브라우저 다운로드를 위한 인터넷 접근)은 이미 갖춰져 있거나 최초 실행 시 한 번 설치·다운로드되는 것을 받아들일 수 있다고 가정한다 — 완전한 오프라인/샌드박스 지원은 이번 범위에 포함하지 않는다(평가 단계 `research.md`/`concept.md` 참고).
- 사용 대상은 이 저장소의 소유자 한 명이며, 팀/커뮤니티 배포는 이번 범위에 포함하지 않는다(평가 단계 `decision.md` 참고).
- Mermaid/ZenUML 계열이 아닌 다이어그램 문법(PlantUML 등) 지원은 이번 범위에 포함하지 않는다.
- 전용 산출물 디렉토리의 이름은 저장소 전역에서 하나로 통일한다(`exports/`) — 산출물 형식(SVG/PNG/PDF)별로 이름을 나누지 않는다.
- 이 저장소에서 다이어그램 소스는 보통 이미 gitignore된 디렉토리(`.zenuml/`) 아래에 있으므로, 전용 산출물 디렉토리를 그 밑에 두면 별도의 `.gitignore` 조정이 필요 없다.
- PNG 해상도 배율은 저장소 전역에서 하나의 고정값을 쓴다(사용자별/요청별로 조정하는 옵션은 이번 범위에 포함하지 않는다) — 구체적인 값은 계획 단계에서 확정한다.

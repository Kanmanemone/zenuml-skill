# Feature Specification: 다이어그램 가장자리 잘림 수정

**Feature Branch**: `005-fix-diagram-clipping`

**Created**: 2026-10-10

**Status**: Draft

**Input**: User description: "exporting-markdown-diagrams 스킬 버그 수정: 일부 렌더러(관찰: zenuml-core)가 루트 SVG의 viewBox를 실제 그려진 내용(메시지 주석, fragment 번호 등)보다 좁게 계산해서, 다이어그램 단독 SVG/PNG/PDF 출력과 문서 전체 PDF에 삽입되는 다이어그램 모두에서 가장자리 내용(예: 가장 오른쪽 lifeline에 붙은 주석, 왼쪽의 fragment 번호)이 잘린다. 렌더링 결과의 실제 그림 범위를 측정해 viewBox가 그것을 모두 덮도록 넓히는 후처리로 해결한다. 원래 잘리지 않던 다이어그램은 바이트 단위로 결과가 바뀌지 않아야 한다(SVG 기준). 근거 자료: 다른 세션의 handoff 문서(HANDOFF-export-clipping.md)의 원인 분석·설계 — 단, 그대로 믿지 말고 독자적으로 검증한 사실에 기반한다. 검증으로 확인된 추가 사실: 기존 mmdc PNG 출력은 mmdc 기본 뷰포트(폭 800) 때문에 폭이 784 CSS px를 넘는 다이어그램을 축소해 찍어 왔다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 다이어그램 단독 export에서 내용이 잘리지 않기 (Priority: P1)

ZenUML 시퀀스 다이어그램에서 가장 오른쪽 참여자에 붙은 메시지 주석이나 왼쪽 가장자리의 fragment 번호처럼, 다이어그램의 원래 경계 밖으로 그려지는 내용이 있다. 이런 다이어그램을 SVG/PNG/PDF로 export했을 때, 지금은 그 내용이 이미지 가장자리에서 잘려 "State 읽기라서 drawBeh"처럼 중간에 끊긴다. 사용자는 다이어그램에 그려진 모든 글자와 도형이 산출물에 온전히 보이기를 원한다.

**Why this priority**: 잘린 산출물은 정보가 빠진 결과물이라 그대로 쓸 수 없다 — 이 스킬의 가장 기본적인 약속(다이어그램을 그대로 파일로 옮긴다)이 깨진 상태다.

**Independent Test**: 가장 오른쪽 참여자에 긴 주석이 붙은 ZenUML 다이어그램 하나를 SVG/PNG/PDF로 각각 export해, 세 산출물 모두에서 주석 전문이 끝까지 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가장 오른쪽 참여자에 긴 주석이 붙어 원래 경계 밖으로 그려지는 ZenUML 다이어그램, **When** PNG로 export하면, **Then** 주석의 마지막 글자까지 이미지 안에 보인다.
2. **Given** 같은 다이어그램, **When** SVG로 export해 브라우저로 열면, **Then** 주석 전문이 보이고 잘린 부분이 없다.
3. **Given** 같은 다이어그램, **When** PDF로 export하면, **Then** 주석 전문이 한 페이지 안에 보이고, 텍스트는 여전히 선택·복사할 수 있다.
4. **Given** 왼쪽 가장자리 밖으로 fragment 번호가 그려지는 다이어그램, **When** 어떤 형식으로든 export하면, **Then** 번호의 첫 글자까지 보인다.

---

### User Story 2 - 문서 전체 PDF에 삽입된 다이어그램도 잘리지 않기 (Priority: P2)

같은 다이어그램이 들어 있는 마크다운 문서 전체를 PDF로 만들 때도, 문서 안에 삽입된 다이어그램이 같은 방식으로 잘리지 않아야 한다.

**Why this priority**: 문서 전체 PDF도 같은 원인으로 잘리지만, 다이어그램 단독 export가 고쳐지면 같은 보정을 재사용할 수 있는 후속 경로다.

**Independent Test**: 잘리던 다이어그램이 포함된 문서를 "1페이지 단일"과 "표준 인쇄 규격" 각각으로 PDF 변환해, 삽입된 다이어그램의 주석 전문이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 잘리던 다이어그램이 포함된 마크다운 문서, **When** 문서 전체를 어느 페이지 구성으로든 PDF로 변환하면, **Then** 삽입된 다이어그램의 가장자리 내용이 모두 보이고 텍스트 선택이 가능하다.

---

### Edge Cases

- 원래 잘리지 않던 다이어그램(일반 Mermaid flowchart/sequence 등): SVG 산출물이 수정 전과 바이트 단위로 같아야 한다. 측정값이 원래 경계를 1단위 미만으로 살짝 넘는 경우(글자·선의 안티에일리어싱 오차)는 넘친 것으로 보지 않는다.
- 원래 경계가 실제 그림보다 넉넉한 쪽(의도된 여백)은 줄이지 않는다 — 넘친 쪽만 넓힌다.
- 한 마크다운 파일에 다이어그램이 여러 개: 각각 독립적으로 보정되고, 기존의 번호 붙은 산출물 이름 규칙(`<base>-1`, `<base>-2` …)이 유지된다.
- 이전 실행에서 남은 같은 이름 패턴의 산출물 파일이 출력 디렉토리에 있어도, 이번 실행이 만든 파일만 결과로 보고된다.
- 렌더러가 그린 다이어그램 자체의 바깥 테두리(ZenUML 프레임)는 그대로 둔다 — 보정된 영역의 내용이 그 테두리 밖으로 보이는 것은 허용한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 다이어그램 단독 export(SVG/PNG/PDF)의 산출물은 다이어그램에 실제로 그려진 모든 내용을 잘림 없이 담아야 한다.
- **FR-002**: 문서 전체 PDF에 삽입되는 각 다이어그램도 FR-001과 같은 보정을 거쳐야 한다(두 페이지 구성 모두).
- **FR-003**: 보정은 렌더링된 결과의 실제 그림 범위를 측정해서 이루어져야 하며, 다이어그램 종류별로 추정하거나 고정 여백을 일괄 추가하는 방식이어서는 안 된다.
- **FR-004**: 경계를 넘친 쪽에만 일정한 작은 여백을 두고 넓혀야 하며, 넘치지 않은 쪽의 경계는 바꾸지 않아야 한다. 1단위 이하의 미세한 넘침은 무시한다.
- **FR-005**: 넘친 곳이 없는 다이어그램의 SVG 산출물은 수정 전 스킬의 산출물과 바이트 단위로 같아야 한다.
- **FR-006**: 보정은 다이어그램의 내용(도형, 글자, 스타일)을 다시 쓰지 않고, 표시 영역(경계와 그에 연동된 최대 표시 폭)만 바꿔야 한다.
- **FR-007**: PNG 산출물은 보정된 다이어그램을 그 실제 레이아웃 크기(축소 없이)에 고정 해상도 배율(기존과 같은 3배)을 곱한 픽셀 크기로, 흰 배경 위에 담아야 한다. 이는 기존 004 스펙 FR-013("다이어그램의 실제 레이아웃 크기에 맞춰 픽셀 수가 정해진다")을 실제로 만족시키는 동작이며, 기존 구현이 폭 784 CSS px를 넘는 다이어그램을 축소해 찍어 온 것을 바로잡는다.
- **FR-008**: 다이어그램 단독 PDF 산출물은 보정된 다이어그램 크기에 정확히 맞춘 한 페이지 벡터 PDF여야 하며, 텍스트를 선택·복사할 수 있어야 한다.
- **FR-009**: 스크립트가 출력하는 산출물 경로 목록에는 이번 실행에서 만들어진 파일만 포함되어야 한다.
- **FR-010**: 스킬의 사용법(호출 인자, 산출물 위치 `exports/`, 산출물 이름 규칙)은 바뀌지 않아야 한다.

### Key Entities

- **다이어그램 표시 영역**: 다이어그램 산출물에서 실제로 보이는 사각형 범위. 렌더러가 계산한 값이 실제 그림 범위보다 좁을 수 있다.
- **실제 그림 범위**: 렌더링된 다이어그램의 모든 도형·글자를 덮는 최소 사각형. 브라우저에서 실측한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 잘림이 재현되는 다이어그램 샘플에서 SVG/PNG/PDF 세 형식 모두, 잘렸던 글자가 100% 보인다.
- **SC-002**: 원래 잘리지 않던 저장소 내 다이어그램 샘플 전부에서 SVG 산출물이 수정 전과 바이트 단위로 같다(회귀 0건).
- **SC-003**: 잘림이 있던 다이어그램을 포함한 문서의 전체 PDF가 두 페이지 구성 모두에서 오류 없이 생성되고, 삽입 다이어그램의 잘렸던 글자가 100% 보인다.
- **SC-004**: 폭이 넓은 다이어그램의 PNG에서 글자가 축소 없이 원래 레이아웃 크기 기준으로 3배 밀도로 찍힌다(PNG 폭 = 다이어그램 폭 × 3, 반올림 오차 범위 내).

## Assumptions

- 잘림의 근본 원인은 렌더러 내부의 경계 계산이며 이 저장소에서 고칠 수 없다 — 렌더링 결과를 사후 보정하는 것이 유일한 현실적 해법이다. (handoff의 원인 분석을 재현 다이어그램으로 독립 검증함: 표시 영역 폭 473.5인데 실제 그림은 838.6까지 그려짐.)
- 실제 그림 범위를 재는 브라우저와 최종 PNG/PDF를 그리는 브라우저는 같은 실행 환경(같은 브라우저 종류·설정)이어야 한다 — 브라우저 종류에 따라 글자 폭이 달라지는 것을 확인했다.
- 보정으로 넓어진 영역의 여백 크기(16단위)와 무시 허용치(1단위)는 handoff의 실측 기반 값을 그대로 쓴다.
- 다이어그램 단독 PDF가 기본 용지 크기 대신 다이어그램 크기 페이지로 바뀌는 것은 수용 가능한 동작 변화로 본다(잘리지 않는 한 페이지가 다이어그램 단독 PDF의 목적에 더 맞음).
- 새 외부 의존성은 추가하지 않는다(필요한 브라우저 자동화 도구는 이미 직접 의존성).

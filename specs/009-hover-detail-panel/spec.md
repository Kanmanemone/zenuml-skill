# Feature Specification: 다이어그램 노드 hover로 책임·협력 보기

**Feature Branch**: `009-hover-detail-panel`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "generating-architecture-views 구조 뷰에서 다이어그램 노드에 마우스를 올리면(hover) 그 노드의 Responsibility와 Collaboration을 그 자리에서 볼 수 있게 한다. 지금은 노드 하나를 이해하려고 다이어그램과 Responsibility·Collaboration 섹션 사이를 스크롤로 오가며 시선을 계속 전환해야 해서 피로도가 크다(문서 내 앵커 하이퍼링크 이동은 시도했지만 잘 작동하지 않았다). 결정된 방향: (1) Mermaid `click` 지시어의 툴팁 자리에 내용을 넣는다 — 툴팁은 고정 문자열만 받으므로 내용은 복사본이다. (2) 원본은 본문(Responsibility·Collaboration)이고, 스킬과 함께 제공하는 스크립트가 본문을 읽어 같은 산출 파일의 `click` 툴팁을 채운다(같은 파일 덮어쓰기, 여러 번 돌려도 결과 같음, 본문을 고친 뒤 따로 다시 실행해 툴팁을 갱신할 수 있음). 모델이 툴팁을 직접 쓰지 않으므로 토큰 영향 없음. (3) 툴팁 기본 모양은 폭 200px라 좁으므로, 산출 md 맨 위에 고정 `<style>` 블록을 넣어 툴팁을 미리보기 아래쪽에 가로로 넓게 고정된 상세 패널(높이 최대 45vh, 왼쪽 정렬)로 바꾼다 — 별도 CSS 파일이나 VS Code 설정 없이 md 하나로 동작해야 한다. 오른쪽 위 고정은 hover 중인 노드를 가려서 버렸다. (4) 대상 환경은 VS Code Markdown 미리보기다. GitHub는 `<style>`과 다이어그램 상호작용을 막으므로 hover를 지원하지 않으며, GitHub에서는 문서가 깨지지 않기만 하면 된다(`<style>` 내용이 본문에 글자로 드러나지 않아야 함 — 미확인). VS Code 미리보기에서 Mermaid 툴팁이 뜨는지와 md 안 `<style>`이 적용되는지도 아직 미확인이며 docs/hover-tooltip-test/ 테스트 키트로 확인 예정. (5) 설정: 기존 settings.jsonc의 responsibility·collaboration 아래에 `hover` 키를 추가한다. responsibility.hover: off / summary(책임 (추상) 한 줄) / full(책임 (추상) + 역할 (구체)), 기본 full. collaboration.hover: off / targets(그 노드가 관여한 협력의 대상과 방향만, 예: → PaymentService (호출)) / full(대상·방향 + 책임의 경계, 분리 이유 & 합리성 평가, 내가 할 수 있는 질문), 기본 targets. display가 hidden이면 hover 값과 상관없이 off로 동작한다. 토큰 영향은 모두 "토큰 소모 영향 없음". (6) 제약: 툴팁 텍스트 안에 큰따옴표 불가, 툴팁은 노드에만 뜨고 엣지에는 안 뜨므로 Collaboration은 노드 기준(→/← 대상)으로 풀어 넣는다, 툴팁은 `click`에 링크가 있어야만 달 수 있으므로 링크 대상이 없는 노드는 hover가 없다(가짜 링크 금지), 패널은 스크롤 불가. (7) 기존 spec 영향: 003의 AP-13c "내용만" 허용 목록에 파일 맨 위 고정 `<style>` 블록을 추가하고, 003의 `click` 툴팁 규칙(지금은 파일 이름)을 hover가 켜지면 내용으로 바뀌도록 고친다. 007 설정 정의(settings.schema.json 포함)에 두 옵션을 추가한다 — 007이 003 규칙에 예외를 추가한 것과 같은 방식으로 기록한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 노드에 마우스를 올려 책임과 협력을 그 자리에서 보기 (Priority: P1)

사용자가 구조 뷰 파일을 VS Code Markdown 미리보기로 열고 Dependency 다이어그램의 노드에 마우스를 올리면, 미리보기 아래쪽에 가로로 넓은 상세 패널이 뜨고 그 노드의 Responsibility와 그 노드가 관여한 Collaboration이 보인다. 마우스를 떼면 패널이 사라진다. 다이어그램에서 시선을 떼고 본문으로 스크롤할 필요가 없다.

**Why this priority**: 사용자가 해결하려는 핵심 문제(다이어그램과 본문 사이를 스크롤로 오가며 생기는 시선 전환 피로)를 직접 해결한다.

**Independent Test**: 링크가 붙은 노드가 여러 개인 구조 뷰를 VS Code 미리보기로 열어, 각 노드에 마우스를 올렸을 때 패널에 그 노드의 본문 내용이 뜨는지, 다이어그램을 미리보기 위쪽에 두었을 때 패널이 노드를 가리지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기본 설정으로 만든 구조 뷰, **When** 사용자가 링크가 붙은 노드에 마우스를 올리면, **Then** 미리보기 아래쪽에 왼쪽 정렬된 넓은 패널이 뜨고, 그 노드의 책임 (추상)·역할 (구체)와 그 노드가 관여한 협력의 대상·방향(예: `→ PaymentService (호출)`, `← OrderController (호출)`)이 보인다.
2. **Given** 같은 구조 뷰, **When** 다이어그램의 오른쪽 아래 끝에 있는 노드에 마우스를 올리면, **Then** 패널이 미리보기 오른쪽이나 아래쪽 경계에서 잘리지 않고 같은 위치에 뜬다.
3. **Given** 본문에서 굵게·코드로 표시된 이름이 있는 항목, **When** 패널이 뜨면, **Then** 굵게·코드 표시가 패널에서도 구분되어 보인다.
4. **Given** 링크 대상이 없는 노드, **When** 그 노드에 마우스를 올리면, **Then** 링크가 있는 노드와 같은 패널이 뜨고, 그 노드를 클릭해도 어디로도 이동하지 않는다.
5. **Given** 구조 뷰 파일, **When** 같은 파일을 GitHub에서 열면, **Then** 패널은 뜨지 않지만 문서는 기존과 같이 보이고, 패널 모양을 정하는 블록의 내용이 본문에 글자로 드러나지 않는다.

### User Story 2 - hover 패널에 넣을 양을 설정으로 고르기 (Priority: P2)

사용자는 스킬 설정 파일의 Responsibility와 Collaboration 아래에서 hover 패널에 넣을 양을 각각 고른다. Responsibility는 넣지 않기·책임 한 줄·책임과 역할 전체 중에서, Collaboration은 넣지 않기·대상과 방향만·대상과 방향에 세부 분석까지 중에서 고른다. 본문 표시 방식(`display`)과는 따로 정한다.

**Why this priority**: 패널은 스크롤이 안 되고 높이가 제한되므로, 노드가 많이 연결된 구조에서는 넣는 양을 줄일 수 있어야 실제로 쓸 수 있다. 다만 P1의 기본값만으로도 기능의 가치는 전달된다.

**Independent Test**: 같은 설명으로 hover 설정 조합을 바꿔 가며 구조 뷰를 만들어, 패널 내용이 설정 값대로 달라지는지와 본문은 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** `responsibility.hover`가 `summary`, **When** 노드에 마우스를 올리면, **Then** 패널에 책임 (추상) 한 줄만 있고 역할 (구체)는 없다.
2. **Given** `collaboration.hover`가 `full`, **When** 노드에 마우스를 올리면, **Then** 패널에 협력의 대상·방향과 함께 책임의 경계, 분리 이유 & 합리성 평가, 내가 할 수 있는 질문이 있다.
3. **Given** 두 `hover`가 모두 `off`, **When** 구조 뷰를 만들면, **Then** 산출 파일은 이 기능 도입 전과 같다(툴팁은 파일 이름, 패널 모양을 정하는 블록 없음).
4. **Given** `responsibility.display`가 `hidden`이고 `responsibility.hover`가 `full`, **When** 구조 뷰를 만들면, **Then** 패널에 Responsibility 내용이 들어가지 않는다(hover가 `off`로 동작).
5. **Given** 설정과 다른 hover 양을 요청 문장에서 직접 밝힌 경우, **When** 구조 뷰를 만들면, **Then** 그 요청에 한해 요청 값이 설정보다 우선한다.

---

### User Story 3 - 본문을 고친 뒤 패널 내용 다시 맞추기 (Priority: P3)

사용자가 이미 만들어진 구조 뷰 파일의 Responsibility나 Collaboration 본문을 직접 고친 뒤, 스킬과 함께 제공되는 도구를 그 파일에 다시 실행하면 패널 내용이 고친 본문에 맞춰진다. 모델에게 구조 뷰를 다시 만들어 달라고 할 필요가 없다.

**Why this priority**: 패널 내용은 본문의 복사본이라 본문만 고치면 둘이 어긋난다. 다시 맞추는 방법이 없으면 복사본이 옛 내용을 보여주게 되지만, 생성 직후에는 둘이 항상 일치하므로 P1·P2보다 뒤에 둔다.

**Independent Test**: 구조 뷰를 만든 뒤 본문의 한 문장을 고치고 도구를 실행해, 패널에 고친 문장이 나오는지와 도구를 한 번 더 실행해도 파일이 바뀌지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 본문의 한 요소 책임 문장을 고친 구조 뷰 파일, **When** 사용자가 그 파일에 도구를 실행하면, **Then** 그 요소의 패널 내용이 고친 문장으로 바뀌고 다른 부분은 바뀌지 않는다.
2. **Given** 방금 도구를 실행한 파일, **When** 도구를 한 번 더 실행하면, **Then** 파일 내용이 바이트 단위로 같다.
3. **Given** 이 기능 도입 전에 만든 구조 뷰 파일, **When** 사용자가 그 파일에 도구를 실행하면, **Then** 패널 내용과 패널 모양을 정하는 블록이 추가되고 본문은 바뀌지 않는다.
4. **Given** 설정에서 두 `hover`를 모두 `off`로 바꾼 뒤, **When** 기존 파일에 도구를 실행하면, **Then** 툴팁이 파일 이름으로 돌아가고 패널 모양을 정하는 블록이 사라진다.

---

### Edge Cases

- **본문에 큰따옴표가 있는 경우**: 툴팁 문자열 안에는 큰따옴표를 쓸 수 없으므로, 패널 내용에서는 다이어그램 문법을 깨뜨리지 않는 다른 표기로 바꿔 넣는다. 본문은 바꾸지 않는다.
- **병렬 형제 요소를 하나로 묶은 Responsibility 항목**(003의 parallel-sibling consolidation): 묶인 각 요소의 패널에 그 묶인 항목 전체를 넣는다 — 항목 안에서 요소별 근거를 잘라내지 않는다.
- **여러 대상을 하나로 묶은 Collaboration 항목**(003의 multi-target consolidation): 출발 노드의 패널에는 묶음 이름(예: `→ feature 내비게이션 요소들 (호출)`)으로, 묶인 각 대상 노드의 패널에는 출발 노드 기준(`← 출발 노드 (호출)`)으로 넣는다.
- **그룹 수준 항목**: 그룹(subgraph)에는 hover가 없으므로 그룹의 책임과 그룹 간 비교는 패널에 넣지 않는다.
- **서로 의존하는 쌍**: 양쪽 노드 패널 모두에 `↔ 상대 (관계)`처럼 양방향으로 표시한다.
- **본문에 해당 노드 항목이 없는 경우**(예: 본문을 사람이 지운 경우): 그 노드의 패널에서 해당 섹션 내용은 비우고, 두 섹션 모두 비면 툴팁을 파일 이름으로 돌린다.
- **패널 높이보다 내용이 긴 경우**: 넘치는 부분은 잘린다. 스크롤은 되지 않는다. 설정으로 넣는 양을 줄여 대응한다.
- **링크 대상이 없는 노드**(003 하이퍼링크 해석 결과 "링크 없음"): 링크 대신 이동하지 않는 형태로 툴팁만 단다(FR-013). 설명에 파일 경로·URL이 전혀 없어도 모든 노드에 패널이 뜬다. 이런 노드도 마우스 커서는 클릭할 수 있는 모양으로 바뀐다.
- **Markdown 링크가 들어 있는 본문**(예: `<strong>[이름](경로)</strong>`): 패널에는 링크 없이 이름 글자만 넣는다(패널은 클릭할 수 없다).
- **구조 변화(동적) 요청의 CRUD 라벨**: 노드 라벨의 ✨/♻️/🗑️ 접두는 패널 내용에 영향을 주지 않는다. 본문 항목을 노드에 대응시키는 데에는 노드 이름을 쓴다.
- **PNG/PDF 내보내기**: 패널은 마우스를 올렸을 때만 뜨므로 내보낸 결과에는 보이지 않으며, 패널 모양을 정하는 블록이 내보낸 결과에 글자로 드러나서도 안 된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `responsibility.hover`나 `collaboration.hover` 중 하나라도 `off`가 아니면(그리고 해당 섹션의 `display`가 `hidden`이 아니면), 스킬은 구조 뷰 파일을 저장한 직후 함께 제공되는 도구를 실행해 각 노드의 툴팁을 그 노드의 패널 내용으로 채워야 한다. 모델은 툴팁 내용을 직접 쓰지 않는다.
- **FR-002**: 패널 내용의 유일한 원본은 같은 파일의 Responsibility·Collaboration 본문이어야 한다. 도구는 본문을 읽어 패널 내용을 만들고 본문 자체는 바꾸지 않는다.
- **FR-003**: 도구는 같은 파일을 덮어써야 하며, 같은 파일과 같은 설정으로 여러 번 실행해도 결과가 같아야 한다(멱등).
- **FR-004**: 도구는 스킬 실행과 별개로, 사용자가 기존 구조 뷰 파일 하나를 지정해 직접 실행할 수 있어야 한다. 이때 hover 양은 설정 파일 값을 따른다.
- **FR-005**: 패널이 들어간 파일은 맨 위에 패널 모양을 정하는 고정 블록(`<style>`) 하나를 가져야 한다. 이 블록은 툴팁을 미리보기 아래쪽에 좌우로 넓게 고정되고, 왼쪽 정렬이며, 높이가 미리보기 높이의 최대 45%인 패널로 바꾼다. 블록 내용은 고정이며 요청마다 달라지지 않는다.
- **FR-006**: 패널 내용이 들어간 노드가 하나도 없으면(두 hover가 모두 `off`이거나 본문에 대응하는 항목이 없는 경우) 파일에는 FR-005 블록도, 링크 없는 노드용 툴팁 줄(FR-013)도 없어야 하고, 링크가 있는 노드의 `click` 툴팁은 기존 규칙(파일 이름)대로여야 한다. 도구는 이 상태로 되돌리는 일도 해야 한다.
- **FR-007**: 별도 CSS 파일이나 편집기 설정 없이 산출 md 파일 하나만으로 VS Code Markdown 미리보기에서 패널이 동작해야 한다.
- **FR-008**: `responsibility.hover` 값은 `off`(넣지 않음), `summary`(책임 (추상) 한 줄), `full`(책임 (추상) + 역할 (구체)) 중 하나이며 기본값은 `full`이다.
- **FR-009**: `collaboration.hover` 값은 `off`(넣지 않음), `targets`(그 노드가 관여한 각 협력의 대상·방향·관계 성격), `full`(`targets` 내용 + 책임의 경계, 분리 이유 & 합리성 평가, 내가 할 수 있는 질문) 중 하나이며 기본값은 `targets`이다.
- **FR-010**: 섹션의 `display`가 `hidden`이면 그 섹션의 `hover`는 값과 상관없이 `off`로 동작해야 한다. 이 경우 설정 안내는 하지 않는다(정상 조합으로 본다).
- **FR-011**: Collaboration은 노드 기준으로 넣어야 한다 — 그 노드가 출발점인 협력은 `→ 대상 (관계)`, 도착점인 협력은 `← 출발 (관계)`, 서로 의존하는 협력은 `↔ 상대 (관계)`로 표시한다. 엣지에는 패널이 없다.
- **FR-012**: 패널 내용은 본문의 굵게·코드 표시를 유지하고, 본문의 Markdown 링크는 링크 없이 글자만 넣으며, 큰따옴표는 다이어그램 문법을 깨지 않는 표기로 바꿔야 한다.
- **FR-013**: 링크 대상이 없는 노드에는 링크를 만들지 않고, 클릭해도 어디로도 이동하지 않는 형태로 툴팁만 달아야 한다(003 FR-027c의 "지어내지 않기"를 그대로 따른다 — 이동 대상을 지어내지 않는다). 이 형태는 VS Code 미리보기에서 클릭 시 오류 표시나 이동을 일으켜서는 안 된다.
- **FR-014**: 요청 문장이 hover 양을 직접 밝히면 그 요청에 한해 요청 값이 설정보다 우선한다(007 FR-006과 같은 규칙).
- **FR-015**: GitHub에서 연 구조 뷰는 패널 없이 기존과 같이 보여야 하며, FR-005 블록의 내용이 본문에 글자로 드러나서는 안 된다. PNG/PDF 내보내기 결과에도 블록 내용이 글자로 드러나서는 안 된다.
- **FR-016** (003 개정): 003의 "산출물에는 실제 내용만" 규칙(FR-032, SKILL.md AP-13c)의 허용 목록에 FR-005의 고정 블록을 추가한다. 이 블록은 메타 코멘트가 아니라 표시 규칙이다.
- **FR-017** (003 개정): 003의 `click` 툴팁 규칙(툴팁은 파일 이름)은 해당 노드에 패널 내용이 있을 때 그 내용으로 바뀐다. 링크 대상 자체(경로·URL)는 바뀌지 않는다. 또 003의 "링크 대상이 없으면 `click`을 두지 않는다" 규칙에, 패널 내용이 있을 때 FR-013의 이동 없는 툴팁 줄을 두는 예외를 추가한다.
- **FR-018** (007 개정): 007의 설정 옵션 목록과 옵션 정의(settings.schema.json)에 `responsibility.hover`와 `collaboration.hover`를 추가하고, 사용자가 고치는 설정 파일(settings.jsonc)에 기존 형식대로 설명 주석과 함께 넣는다. 두 옵션의 모든 값의 토큰 영향 표기는 "토큰 소모 영향 없음"이다. 잘못된 값 처리는 007 FR-005를 따른다.

### Key Entities

- **노드 패널 내용**: 노드 하나에 대한 툴팁 문자열(링크 유무와 무관). Responsibility 부분(설정 값에 따라 없음/책임 한 줄/책임+역할)과 Collaboration 부분(설정 값에 따라 없음/대상 목록/대상 목록+세부 분석)으로 이뤄진다. 원본은 같은 파일의 본문이다.
- **패널 모양 블록**: 파일 맨 위에 놓이는 고정 `<style>` 블록. 패널 내용이 있는 노드가 하나라도 있을 때만 존재한다.
- **hover 설정**: `responsibility.hover`, `collaboration.hover`. 각 섹션의 `display`와 독립적으로 정하되, `display`가 `hidden`이면 `off`로 동작한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: VS Code Markdown 미리보기에서 모든 노드(100%, 링크 유무와 무관)에 마우스를 올렸을 때, 스크롤 없이 그 노드의 Responsibility와 관여한 협력 대상이 보인다.
- **SC-002**: 다이어그램을 미리보기 위쪽에 둔 상태에서, 어느 노드에 마우스를 올려도 패널이 그 노드를 가리지 않고 미리보기 경계에서 잘리지 않는다.
- **SC-003**: 생성 직후 모든 노드의 패널 내용이 같은 파일 본문과 100% 일치한다(설정 값에 따른 범위 안에서).
- **SC-004**: 도구를 같은 파일에 연달아 두 번 실행했을 때 두 번째 실행은 파일을 바꾸지 않는다.
- **SC-005**: 두 hover가 모두 `off`인 설정으로 만든 산출 파일은 이 기능 도입 전 규칙으로 만든 파일과 같다.
- **SC-006**: 같은 파일을 GitHub와 PNG/PDF 내보내기로 봤을 때 패널 모양 블록의 내용이 글자로 드러나는 경우가 0건이다.
- **SC-007**: 이 기능을 켜도 구조 뷰 한 번 생성에 드는 모델 출력 분량이 늘지 않는다(패널 내용은 도구가 만든다).

## Assumptions

- 대상 미리보기는 VS Code 내장 Markdown 미리보기(Mermaid 12)다. 다른 미리보기에서의 동작은 보장하지 않는다.
- **선행 확인(미확인)**: VS Code 미리보기에서 (1) Mermaid 노드 툴팁이 뜨는지, (2) md 안 `<style>`이 적용되는지, 그리고 GitHub에서 (3) `<style>` 내용이 글자로 드러나지 않는지를 `docs/hover-tooltip-test/`로 확인한다. (1)이나 (2)가 안 되면 이 spec의 방향을 다시 정해야 하고, (3)이 안 되면 FR-015를 만족할 다른 표기를 찾아야 한다. 일반 브라우저(Mermaid 12.3, strict 보안 수준)에서는 세 가지 모두 의도대로 동작함을 확인했다.
- 패널은 스크롤할 수 없고 마우스를 노드에서 떼면 사라진다. 이는 Mermaid 툴팁의 고정 동작이며 바꾸지 않는다.
- 툴팁을 지정하는 문법은 `click` 줄뿐이지만 링크가 필수는 아니다. 일반 브라우저(Mermaid 12.3, strict)에서 링크 대신 콜백 이름을 쓴 `click` 줄도 툴팁이 뜨고, 클릭해도 이동·오류가 없음을 확인했다. VS Code 미리보기에서도 같은지는 선행 확인 항목에 포함한다.
- 도구를 따로 실행할 때는 설정 파일 값만 따른다. 요청 문장으로 설정과 다른 hover 양을 썼던 파일에 도구를 다시 실행하면 설정 값으로 맞춰진다.
- 설정의 초기값(`full`, `targets`)은 사용자가 정했다(007 FR-003의 "사용자가 항목별로 지정" 원칙).
- 이 기능은 `generating-architecture-views`에만 적용한다. `generating-zenuml-diagrams`의 시퀀스 다이어그램은 대상이 아니다.
- 피드백 로그 형식은 바꾸지 않는다.

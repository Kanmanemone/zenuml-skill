# Data Model: 다이어그램별 개선 이력 로깅

이 기능은 데이터베이스나 영속 저장소를 갖지 않는다. 아래 "엔티티"는 skill 실행 중 다뤄지는 개념적 대상과 그 속성을 정리한 것이며, spec.md의 Key Entities를 구체화한다.

> **개정**: 이전 판은 "다이어그램 피드백 로그"와 "다이어그램 산출물"을 한 파일로 통합했으나, spec.md의 최종 결정에 따라 다시 **두 개의 독립된 엔티티**로 분리했다 — 갱신 방식(교체 vs 누적)이 근본적으로 다르기 때문이다. 대신 이번 판에는 요청 종류 판단을 위한 새 엔티티("요청 분류")를 추가했다.

## 요청 분류 (Request Classification)

다이어그램을 만들기 전에 매번 수행되는 판단. 영속 데이터는 아니지만 이후 모든 동작을 결정하는 워크플로의 진입점이므로 가장 먼저 기록한다.

| 속성 | 설명 |
|------|------|
| outcome | `최초 생성` \| `재생성` \| `slug 충돌로 인한 새 요청` 중 하나 |
| basis | 판정 근거 — 대화 맥락(직전 다이어그램에 대한 변경 요청인지) + 도출된 slug의 파일 존재 여부 |

**판정 규칙**:
1. 이번 요청이 이번 대화(세션) 안에서 방금 제시한 다이어그램에 대한 변경 요청이면 → `재생성`. 대상은 그 직전 다이어그램(slug).
2. 그렇지 않고, 도출된 slug의 산출물 파일이 아직 없으면 → `최초 생성`.
3. 그렇지 않고, 도출된 slug의 산출물 파일이 이미 있지만 이번 요청은 그것과 무관한 별개의 새 다이어그램이면 → `slug 충돌로 인한 새 요청`(feature 001의 기존 `-2`, `-3` 충돌 규칙 적용, 그 변형 slug로 `최초 생성` 취급).

**검증 규칙**: 판정이 애매하면 추측하지 않고 명확화 질문으로 되묻는다 — 다이어그램 생성도, 파일 쓰기도 판정이 끝나기 전에는 시작하지 않는다.

## 다이어그램 산출물 (Diagram Output)

`.zenuml/<slug>.md` — feature 001이 이미 만드는 바로 그 파일.

| 속성 | 설명 |
|------|------|
| file_path | `.zenuml/<slug>.md` |
| current_diagram | 가장 최근에 생성/재생성된 ZenUML 원문 (Mermaid `zenuml` 코드펜스) |

**상태 변화**: `요청 분류`가 `재생성`이면 이 파일은 **전체 교체**된다 — 이전 내용은 남지 않는다. `최초 생성`/`slug 충돌로 인한 새 요청`이면 새로 만들어진다.

## 다이어그램 피드백 로그 (Diagram Feedback Log)

`.zenuml/log/<slug>.md` — 다이어그램 산출물과 slug는 같지만 별개의 파일.

| 속성 | 설명 |
|------|------|
| file_path | `.zenuml/log/<slug>.md` |
| rounds | 교정 라운드(아래 참조)의 순서 있는 목록. append-only — 기존 라운드는 절대 수정·삭제되지 않는다 |

**존재 조건**: 다이어그램이 처음 생성되는 순간 첫 라운드와 함께 만들어진다 — 다이어그램 산출물과 항상 짝을 이뤄 존재한다(spec.md User Story 1).

## 교정 라운드 (Correction Round)

다이어그램 피드백 로그 안의 한 단위.

| 속성 | 설명 |
|------|------|
| round_number | 1부터 시작 (Round 1 = 최초 요청) |
| date | 라운드가 발생한 ISO 8601 날짜 |
| request_text | 그 시점 사용자 요청 원문(최초 요청이든 재생성 요청이든) |
| response | 그 요청에 대한 응답 — 생성/재생성된 ZenUML 원문(Mermaid `zenuml` 코드펜스) 포함 |

**불변 조건**: 한번 기록된 라운드는 이후 라운드가 추가되어도 내용이 바뀌거나 삭제되지 않는다(spec.md FR-004).

## 인용 스테이징 컨벤션 (Citation Staging Convention)

`.claude/skills/generating-zenuml-diagrams/SKILL.md`에 문서화되는, 데이터가 아닌 절차적 규칙.

| 속성 | 설명 |
|------|------|
| trigger | 어떤 작업이 특정 다이어그램 피드백 로그(`.zenuml/log/<slug>.md`)를 실제로 읽고 근거로 인용하기로 결정한 시점 |
| action | `git add -f <해당 로그 파일 경로>` — 그 파일 하나만 강제 스테이징 |

**적용 범위**: 다이어그램 산출물(`.zenuml/<slug>.md`)은 대상이 아니다 — 재생성마다 교체되어 이력 가치가 없기 때문이다(spec.md FR-007이 "로그 파일"만 명시).

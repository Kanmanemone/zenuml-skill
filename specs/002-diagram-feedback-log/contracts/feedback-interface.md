# Contract: `generating-zenuml-diagrams` Skill Interface — 개선 이력 로깅 확장

이 문서는 `specs/001-zenuml-diagram-skill/contracts/skill-interface.md`가 정의한 기존 계약에 **추가**되는 부분만 다룬다.

> **개정**: 이전 판들(별도 로그 디렉토리+스냅샷 파일, 이후 단일 누적 파일, 이후 AskUserQuestion/하드코딩 텍스트 메뉴)은 모두 폐기됐다. 최종 설계는 확인 질문이 전혀 없고, 워크플로 맨 앞에서 요청 종류를 판단한 뒤 산출물(교체)과 로그(누적)를 분리해서 다룬다.

## 0단계 — 요청 종류 판단 (가장 먼저 수행)

다이어그램을 만들거나 파일을 건드리기 전에, 반드시 먼저 판단한다(data-model.md, 요청 분류 참고):

1. 이번 요청이 이번 대화에서 방금 제시한 다이어그램에 대한 변경 요청인가? → **재생성**.
2. 아니고, 도출된 slug의 산출물 파일이 없다면 → **최초 생성**.
3. 아니고, 도출된 slug의 산출물 파일이 있지만 이번 요청과는 무관하다면 → **slug 충돌로 인한 새 요청**(기존 `-2`/`-3` 규칙 적용 후 최초 생성으로 취급).
4. 판단이 애매하면 다이어그램을 만들지 않고 명확화 질문으로 되묻는다(feature 001의 기존 패턴 재사용).

이 판단 없이는 이후 어떤 단계도 시작하지 않는다 — 잘못된 파일을 교체하거나 엉뚱한 로그에 이어붙이는 사고를 막기 위함이다.

## Output Contract — 최초 생성 (또는 slug 충돌로 인한 새 요청)

기존 `skill-interface.md`의 생성 규칙(설명에 없는 내용을 지어내지 않음, AP-1~AP-5 자기검증, 명확화 필요 시 질문, 범위 밖 안내)을 그대로 따른다. 다이어그램이 실제로 생성되면, 추가로:

1. `.zenuml/<slug>.md`를 새로 만들어 생성된 ZenUML 코드펜스를 담는다(기존 feature 001 동작, 변경 없음).
2. `.zenuml/log/<slug>.md`를 새로 만들어 `## Round 1`로 최초 요청 원문과 응답(생성된 다이어그램 포함)을 기록한다.

```text
<.zenuml/<slug>.md 를 가리키는 상대 경로 링크 한 줄 — 기존 Output File 계약과 동일>
```

## Output Contract — 재생성

1. 전달된 요청을 반영해 다이어그램을 재생성한다 — 생성 규칙과 AP-1~AP-5 자기검증을 동일하게 적용한다.
2. `.zenuml/<slug>.md`를 **새 내용으로 완전히 교체**한다 — 이전 내용은 남기지 않는다.
3. `.zenuml/log/<slug>.md`에 새 `## Round N — <날짜>` 절(이번 요청 원문 + 응답)을 이어붙인다 — 기존 라운드는 절대 수정·삭제하지 않는다.
4. 갱신된 다이어그램을 사용자에게 다시 제시한다 — 코드 미노출, `.zenuml/<slug>.md`를 가리키는 링크(최초 제시 때와 같은 링크, 내용만 갱신됨).

```text
<.zenuml/<slug>.md 를 가리키는 상대 경로 링크 한 줄 — 내용은 최신으로 교체됨>
```

## Output Contract — 판단이 애매할 때

새 다이어그램을 만들거나 기존 파일을 건드리지 않고, 재생성인지 최초 생성인지를 구체적으로 되묻는다. 이 질문은 확인용 선택 UI가 아니라 feature 001이 이미 갖고 있는 "명확화 질문" 패턴이다 — 다이어그램 구조 자체가 불명확할 때 쓰는 것과 같은 방식으로, 이번엔 "요청 종류"가 불명확할 때 쓴다.

## 다이어그램 파일 자체의 Contract

- `.zenuml/<slug>.md`: 항상 최신 상태 하나만 담는다(data-model.md, 다이어그램 산출물).
- `.zenuml/log/<slug>.md`: 요약·분석·패턴 자동 탐지 없이, 라운드를 있는 그대로 누적한다(spec.md FR-008; data-model.md, 다이어그램 피드백 로그·교정 라운드).

## 인용 시 스테이징 Contract

이 skill 자체는 파일을 쓰기만 하고, 인용 감지는 하지 않는다. `SKILL.md`에 문서화된 컨벤션(data-model.md, 인용 스테이징 컨벤션)을 따라, `.zenuml/log/<slug>.md`를 실제로 읽고 인용하는 **다른 작업**이 `git add -f`로 그 로그 파일 하나만 선별 스테이징한다. 다이어그램 산출물(`.zenuml/<slug>.md`)은 이 컨벤션의 대상이 아니다. 이 skill의 SKILL.md는 컨벤션을 문서화만 할 뿐, 다른 작업을 호출하거나 다른 스킬 파일을 수정하지 않는다.

## Error/Fallback Behavior

파일 저장 불가 환경, 범위 밖 요청은 기존 `skill-interface.md`의 분기를 그대로 따른다 — 그 경우 0단계(요청 종류 판단)와 이후 로깅 단계 전체가 적용되지 않는다(저장할 파일 자체가 없으므로).

# 스코프 트리 계약 (2026-11-17, 아래 모든 계약보다 우선)

**명령**: `prepare`와 `build`(그대로). 설정, `stage1-prompt.md`, 문서의 상자·diff·책임 줄 형식은 바꾸지 않는다.

**`prepare`** 출력: JSON 한 줄(그대로) 뒤에, 구체화하는 노드마다 아래 블록을 낸다. 자식이 없는 루트(본문 없는 선언)는 블록을 내지 않는다.

```text
===== <id> · 책임: <책임 한 줄 또는 "없음"> · 스코프 <k>개 =====
--- #<n> (부모 #<m> | 루트)
<표시>| <원본 줄>
…
```

- 표시는 다음과 같다.
  - `-`: 이 스코프의 자기 줄
  - `<자식 번호>`: 그 자식의 첫 줄
  - 빈칸: 리프 자식의 이어지는 줄
  - `=`: 붙는 선언(루트에만 나오며, 묶지 않음). 한 줄 선언뿐이며, 여러 줄 비공개 멤버는 루트의 자식 번호로 나온다(2026-11-18)
- 스코프 자식은 `<자식 번호>| <들여쓰기>⟨#<스코프 번호>⟩` 한 줄로 접힌다.
- 스코프는 후위 순서다. 원본 범위의 모든 줄은 블록 전체에서 정확히 한 번 나온다.

**`outline.json`**: [data-model.md](../data-model.md)의 형식이다. 한 스코프 항목을 한 줄에 쓴다.

```json
{"BulletedListTextField": [
  {"s": "스크롤된 만큼 그리기 원점을 옮긴다.", "with": [3, 4], "sep": [{"ids": [1, 2], "s": "스크롤 오프셋을 구한다."}]},
  …,
  {"sep": [{"ids": [1, 2, 3], "s": "불릿 칸의 폭을 불릿 글자 크기로 정한다."}, {"ids": [4]}]}
]}
```

**`build`** 거부(종료 코드 2): 틀린 곳마다 한 줄씩 `<id> 스코프 #<n>: <이유>`를 표준 오류로 낸다.
- 1단계 파일이나 `outline.json`이 없음
- 노드 항목이 없음, 또는 배열 길이가 스코프 수와 다름
- 자식을 빠뜨리거나 두 번 덮음, 없는 자식 번호
- `sep` 5개 이상, 루트에 `s`·`with`가 있음
- 문장 없음(루트가 아닌 스코프의 `s`, 리프가 있거나 둘 이상인 묶음의 `s`)
- 문장 규칙 위반(research S5)

트리 불변식이 깨지거나, 모두 연 장면이 원본과 다르거나, 원본이 바뀌었으면 종료 코드 3이다.

**장면**(research S6)
- 윤곽: 선언 머리(쓰이지 않은 매개변수는 `...`), 그리고 루트의 묶음마다 `⟨번호. 문장⟩`과 그 아래 들여 쓴 안쪽 단계들
- 펼치기 n: 1~n단계의 노드 줄과 붙는 선언을 원본 그대로 보이고, 남은 단계는 같은 번호의 자리표시자로 둔다
- 제목: `<k>단계: <별명> <n>/<N> — <묶음 문장> (<k>/<전체>)`
- 마지막으로 보이는 코드 장면이 원본과 같으면 원본 장면을 두지 않는다(기존 규칙 그대로). 펼치기를 모두 보이면 늘 이 경우이고, 설정으로 펼치기를 끄면 윤곽 다음에 원본이 나온다. diff는 연속한 코드 장면끼리다.

# Contract: 단계 정의 파일, `stages.py`, 산출물 형식

## 1. 단계 정의 파일 `stages.md`

위치는 `.agents/skills/revealing-code-step-by-step/stages.md`이다.

```markdown
# 단계 정의

(자유 설명 — 스크립트는 읽지 않는다. 1원칙, 구체화 사다리 요약, spec 링크)

## 꾸며낸 뼈대

- 원본과 같아지는 것: 없음(노드 이름만 구조 뷰와 같음)
- 아직 드러나지 않은 것: 전부(원본을 모르고 지어낸 코드로 채움)

## 선언의 종류

- 원본과 같아지는 것: …
- 아직 드러나지 않은 것: …
- 보조 표기: 1단계의 지어낸 본문을 `⟨설명⟩`으로 바꾼다 …

(이하 단계마다 반복)
```

- **단계 하나의 형태**: `## ` 제목 하나와 그 아래 항목들이다. 스크립트가 읽는 항목 머리는 정확히 `- 원본과 같아지는 것:`과 `- 아직 드러나지 않은 것:` 둘이다. `- 보조 표기:`와 그 밖의 문단은 모델만 읽는다.
- **처음 내용**: spec FR-008의 7단계 표와 그 아래 문단을 옮긴다. 옮긴 뒤 spec의 FR-008에는 이 파일의 링크만 남긴다.
- **오류(종료 코드 2)**: 다음 중 하나라도 해당하면 오류로 끝난다.
  - 단계가 2개 미만
  - 별명이 겹침
  - 필수 항목이 하나라도 없음

## 2. 실행 규약

```text
<python> <skill>/scripts/stages.py prepare <구조 뷰 파일> [--show=<별명,…>] [--hide=<별명,…>] [--output-dir=<상대 경로>] [--pick=<id>:<번호>,…]
<python> <skill>/scripts/stages.py begin   <산출 폴더> <단계 번호>
<python> <skill>/scripts/stages.py apply   <산출 폴더> <단계 번호>
<python> <skill>/scripts/stages.py build   <산출 폴더>
```

- 작업 폴더를 바꾸지 않고 실행한다. 경로는 프로젝트 루트를 기준으로 한다.
- 표준 출력에는 결과 JSON 한 줄을 낸다(`begin`은 그 뒤에 코드를 더 출력한다). 오류는 표준 오류에 한국어 한 줄로 내고, 0이 아닌 종료 코드로 끝난다.

| 코드 | 뜻 | 예 |
|---|---|---|
| 0 | 성공 | |
| 2 | 입력 문제 | 구조 뷰 형식이 아님, 노드가 없음, `stages.md` 오류, 작업 파일 누락, 이미 시작한 단계, 적용할 수 없는 바꿀 내용 |
| 3 | 마지막 단계가 원본 범위와 다름 | `build` 확인 실패 |

### `prepare <view>`

1. 다음 경우에는 종료 코드 2로 끝난다.
   - `<view>`가 `*.architecture.md`가 아님
   - `### Dependency` 아래에 Mermaid 블록이 없음
   - 노드가 없음
2. 설정(`settings.jsonc`)을 읽는다. 요청 옵션(`--show`, `--hide`, `--output-dir`)이 있으면 이번 실행에서 설정보다 우선한다(research R12). 산출 폴더는 `<view 폴더>/<output.directory>/<slug>.stages/`다. 이 폴더가 있으면 통째로 지우고 새로 만든다(FR-020). 지우는 것은 이 폴더뿐이다(FR-019a).
3. 단계 정의와 보이기 값으로 만들 단계 목록을 정한다(research R13).
4. 노드, 그룹, 링크를 읽고([data-model.md](../data-model.md)의 Node), 문서를 어떻게 나눌지 정한다(Document).
5. 노드마다 원본을 읽고 원본 범위를 찾는다(research R5, R8, S10, S11). 언어 프로필이 있는 원본은 노드 이름의 선언을 먼저 찾는다. 선언이 없거나 프로필이 없으면, 노드 Id나 표시 이름이 파일 이름·확장자 뺀 이름·Kotlin 파일 클래스 이름(`<확장자 뺀 이름>Kt`)과 같을 때 파일 전체를 원본 범위로 한다(`range.whole_file`). 찾으면 `work/original/<id>.kt`에 바이트 그대로 쓴다. 이 파일은 줄바꿈 하나로 끝난다. 찾지 못하면 `skip_reason`을 다음 중 하나로 정한다.

   | 경우 | `skip_reason` |
   |---|---|
   | 링크 없음 | `원본 위치가 없어 구체화하지 않음` |
   | 폴더이거나 파일 하나로 정해지지 않음 | `링크가 파일 하나를 가리키지 않아 구체화하지 않음` |
   | 없거나 받지 못함 | `원본을 읽을 수 없어 구체화하지 않음 (<원인>)` |
   | UTF-8 아님 | `원본을 UTF-8로 읽을 수 없어 구체화하지 않음` |
   | 블록 구조를 아는 언어(S11): 선언 0개이고 파일 단위 노드도 아님 | `원본 파일에서 <이름> 선언을 찾지 못해 구체화하지 않음` |
   | 블록 구조를 아는 언어, Kotlin 밖: 찾은 범위가 블록 구조로 확인되지 않고 파일 단위 노드도 아님 | `원본 파일에서 <이름> 선언 범위를 블록 구조로 확인하지 못해 구체화하지 않음` |
   | 프로필이 없는 원본(마크업·데이터 파일, 목록 밖 언어): 파일 단위 노드가 아님 | `블록 구조를 모르는 원본은 파일 단위 노드만 원본 범위를 정할 수 있어 구체화하지 않음` |
   | 선언 2개 이상이고 `--pick` 없음 | `원본 파일에 <이름> 선언이 여럿 — --pick으로 하나를 골라야 함` (노드에 `candidates`가 붙는다. 모델이 고른 뒤 `--pick`으로 다시 실행) |

6. 만들 단계 목록과 노드 정보를 `work/manifest.json`에 적는다. `begin`·`apply`·`build`는 `stages.md`가 아니라 이 사본을 쓴다. 한 번 만드는 동안 정의가 바뀌지 않게 하기 위해서다.
7. 1단계 서브에이전트에게 줄 지시 전부를 `work/stage1-prompt.md`에 쓴다(research R1). 스킬 폴더의 `stage1-prompt.md` 틀에 1단계 정의(`별명 — becomes / unrevealed`), 노드마다 `- <id> (<이름>) → <1단계 파일의 절대 경로>` 한 줄, 구조 뷰 파일 내용 전부를 채운 것이다.
8. 출력 JSON은 아래 형태다. 모델이 다음에 할 일에 필요한 것만 담는다.

```json
{"dir": ".zenuml/<slug>.stages",
 "stage1_prompt": "<절대 경로>/work/stage1-prompt.md",
 "middle": [2, 3, 4, 5, 6],
 "pick": [{"id": "Screen", "source": "<원본 경로>", "candidates": [{"pick": 1, "start_line": 3, "end_line": 7, "header": "…"}, …]}]}
```

- `middle`: 모델이 `begin`·`apply`를 실행할 단계 번호(2…g-1)다.
- `pick`: `--pick`이 필요한 노드다. 비어 있지 않으면 모델이 후보를 골라 `prepare`를 다시 실행한다.

### `begin <dir> <k>`

- 다음을 모두 만족해야 한다. 하나라도 어긋나면 종료 코드 2로 끝난다.
  - `2 ≤ k ≤ g-1` (`g`는 만드는 단계 수, research R13)
  - `work/<k-1>`이 있음
  - `work/<k>`가 없음
  - 직전 단계의 작업 파일이 모두 있음(k = 2이면 모든 노드의 1단계 파일, 그 밖에는 구체화하는 노드의 파일). 빠지면 빠진 경로를 모두 적는다.
- 구체화하는 노드마다 `work/<k-1>/<id>.kt`를 `work/<k>/<id>.kt`로 그대로 복사한다. 구체화하지 않는 노드는 복사하지 않는다. 남아 있는 `work/edits.txt`는 지운다.
- 폴더 이름의 번호는 두 자리다(`01`, `02`, …).
- 출력의 첫 줄은 `{"stage": k, "nickname": "…", "becomes": "…", "unrevealed": "…", "notation": "…", "merged": [{"nickname": "…", "becomes": "…", "notation": "…"}], "edits": "<dir>/work/edits.txt"}` 형태의 JSON이다. `merged`는 꺼져서 이 단계에 합쳐진 단계들의 몫이고, 모델은 이것까지 함께 바꾼다.
- 그 뒤에 구체화하는 노드마다 복사한 코드를 `===== <id> · <k>단계 =====` 머리 아래에 그대로 출력한다. 원본 범위 안에 다른 노드가 들어 있으면 머리에 ` · 안에 든 노드: <id>, …`를 붙인다. k = 2일 때는 노드마다 원본 범위도 `===== <id> · 원본 =====` 머리 아래에 출력한다. 모델이 작업 파일을 따로 읽지 않게 하기 위해서다.

### `apply <dir> <k>`

- 모델이 `work/edits.txt`에 적은 바꿀 내용을 k단계 작업 파일에 적용한다(research R11). 형식은 아래 블록의 반복이다. 블록 밖에는 빈 줄만 올 수 있다.

  ```text
  <<<<<<< <node id>
  바꿀 글(지금 파일에 있는 그대로, 여러 줄 가능)
  =======
  새 글(비우면 그 줄들을 지운다)
  >>>>>>>
  ```

- 다음 중 하나라도 어긋나면 종료 코드 2로 끝나고, 어떤 파일도 바꾸지 않는다.
  - k단계가 시작되었고(`work/<k>`가 있음) 다음 단계는 아직 시작되지 않았음
  - `work/edits.txt`가 있고 형식이 맞음
  - 블록마다 노드가 구체화하는 노드이고, 바꿀 글이 그 파일(앞 블록을 적용한 뒤)에 정확히 한 번 나옴
- 성공하면 파일을 쓰고 `work/edits.txt`를 지운 뒤, k단계를 k-1단계와 기계적으로 비교해 `warnings`를 낸다.
  - 원본 범위에 있는 줄(공백을 뺀 글자 기준, 글자나 숫자가 하나라도 있는 줄)이 k-1단계에 있었는데 k단계에서 사라졌으면 그 줄을 알린다(1원칙, FR-012).
  - 노드 이름(Id나 식별자인 표시 이름)이 코드에 없으면 알린다.
- 출력 JSON은 `{"stage": k, "changed": ["<id>", …], "warnings": ["…", …]}` 형태다. 모델은 다음 `begin` 전에 경고를 고친다.

### `build <dir>`

1. 작업 파일을 확인한다. `work/01`의 모든 노드 파일과, 2…g-1단계마다 구체화하는 모든 노드 파일이 있어야 한다. 빠진 것이 있으면 종료 코드 2로 끝나고 빠진 목록을 출력한다.
2. 노드마다 단계별 코드를 정한다.
   - 1…g-1단계: 작업 파일
   - g단계(마지막): `work/original/<id>.kt`
   - 구체화하지 않는 노드: 1단계 하나뿐
3. 문서마다 `<dir>/<doc>.md`를 쓴다(3절).
4. 쓴 문서를 다시 읽는다. 구체화하는 노드마다 마지막 단계의 코드 블록 내용을 꺼낸다. 원본 위치에서 파일을 다시 읽고(R8) 다시 잘라낸 구간(R5)과 비교한다. 줄바꿈 종류는 LF로 맞춘다. 하나라도 다르면 종료 코드 3으로 끝나고, 그 노드와 첫 번째로 다른 줄 번호를 출력한다. 이때 문서는 지우지 않는다.
5. 출력 JSON은 아래 형태다.

```json
{"docs": [".zenuml/…/all.md", …],
 "unchanged": {"<별명>": ["<id>", …]},
 "skipped": [{"node": "…", "reason": "…"}],
 "verified": <개수>,
 "notices": ["⚙️ 설정 안내: …"],
 "reply": "📄 [<문서 title>](<문서 경로>)\n…\n⚠️ <노드>: <이유>\n…"}
```

- `reply`: 채팅 응답 전체다. 문서마다 `📄` 한 줄, 구체화하지 않은 노드마다 `⚠️` 한 줄, 설정 알림을 차례로 담는다.

- `unchanged`: "달라진 것이 없음"이 붙은 노드 목록이다.

## 3. 문서 형식

줄 끝은 LF이고, 파일은 줄바꿈 하나로 끝난다. 구조는 [prototype/code-gallery.md](../prototype/code-gallery.md)를 따르고, 거기에 노드의 책임 줄과 단계 제목·표시 줄을 더한다.

- **책임 줄**(spec FR-015e): 노드 제목과 상자 사이, 상자 바깥에 둔다. 단계에 속하지 않으므로 단계마다 반복하지 않는다. 문장은 구조 뷰 `#### 요소의 책임`에서 그 노드 항목의 `책임 (추상)` 값을 글자 그대로 옮기고, HTML로 이스케이프한다. `역할 (구체)`는 옮기지 않는다. 값이 없거나 `설명에 명시되지 않음`으로 시작하면 이 줄을 두지 않는다. 여러 노드가 한 항목에 묶여 있으면 묶인 노드마다 같은 문장을 둔다. `.resp`는 왼쪽 회색 막대와 옅은 회색 배경의 띠이고, `.label`은 굵고 옅게 보인다.
- **제목**: `<k>단계: <별명> (<k>/<n>)` 형식이다(spec FR-015).
- **표시 줄**: 2단계 이후이고 직전 단계와 같을 때만 제목 아래에 `<div class="note">이 단계에서는 달라진 것이 없음</div>`을 둔다. 그 밖의 단계에는 표시 줄이 없다. 단계의 `becomes`는 화면에 적지 않는다.
- **달라진 줄 색칠**(research R7, VS Code의 git 변경 표시 규칙): 2단계부터 직전 단계와 비교해 줄마다 종류를 정한다.
  - `add`(추가): 왼쪽 초록 막대 + 옅은 초록 줄 배경
  - `mod`(변경): 왼쪽 파란 막대 + 옅은 파란 줄 배경
  - `del`(그 줄 바로 위에서 지워짐): 빨간 삼각형. 끝에서 지워졌으면 마지막 줄에 `del-after`를 붙인다.

  diff 층(`pre.diff`)은 줄마다 span 하나를 두고, 그 안에 그 줄의 코드 글자를 이스케이프해 그대로 넣는다. 글자색은 투명이다. 종류는 클래스로 단다. 한 줄에 `add`와 `del`이 함께 붙을 수 있다. 줄 수는 코드 줄 수와 같다. 1단계와 "달라진 것이 없음"인 단계에는 diff 층을 두지 않는다.
- **기존 상자와 diff 층의 경계**(research R7의 다섯 원칙): 이 경계는 다음 세 가지로 확인할 수 있어야 한다.
  - 기존 상자의 마크업과 첫 번째 `<style>`은 diff 층을 모른다.
  - diff 층은 `pre.diff` 요소들과 두 번째 `<style>`로만 이뤄진다. 코드 위에 절대 위치로 얹히고, 자리를 차지하지 않으며, `pointer-events: none`이다.
  - 문서에서 `pre.diff` 요소와 두 번째 `<style>`을 지우면, 그 문서는 같은 단계 코드로 diff 층 없이 만든 문서와 바이트 단위로 같다.
  - 두 `<style>`은 파일 끝의 `details.zenuml-stepwise-style` 하나 안에 있고, 첫 번째 CSS가 편집기 미리보기에서 wrapper를 숨긴다. GitHub에서는 요약 한 줄을 펼칠 때만 CSS 원문이 보인다.
- **코드 블록**: 펜스 길이는 코드 안에서 가장 긴 백틱 연속보다 하나 더 길게 한다(최소 3).
- **`.code` 영역**(기존 상자의 몫): 코드의 높이 상한 `min(30lh, 70vh)`과 세로·가로 스크롤을 맡는다. 코드는 `white-space: pre`로 줄바꿈하지 않는다.
- **diff 층 CSS**(두 번째 `<style>`): `.code`를 기준점으로 삼아 `pre.diff`를 코드 위에 겹친다. 줄 위치는 `pre > code` 구조와 글자가 같아서 맞는다(research R7 원칙 4). 기존 상자의 여백·줄 높이 수치를 베끼지 않는다. 가로·세로로 스크롤해도 줄을 따라간다. 색은 `--vscode-editorGutter-addedBackground`·`modifiedBackground`·`deletedBackground` 테마 변수를 쓰고, 대체 색을 함께 적는다.
- **구체화하지 않는 노드**: `### <노드 이름>` 아래(책임 줄이 있으면 그 아래)에 `⚠️ <skip_reason>` 한 줄을 두고, 상자에는 1단계 하나만 둔다(spec FR-017, 넘길 단계 없음).
- **같은 문서에서 Id가 겹치는 경우**: 라디오의 `name`과 `id`는 노드 Id로 만든다. 노드 Id는 구조 뷰 안에서 유일하다.
- 문서에는 단계 코드, 책임 줄, 위 표시만 담는다(FR-018).

# 단위 펼치기 계약 (아래 앞선 계약보다 우선)

**정의**: `- 표현: prose|outline|unfold|source`. 첫 단계는 `prose`, 마지막은 `source`여야 한다. `unfold`는 노드마다 단위 수만큼 반복된다. `- 반복:` 필드는 없다.

**명령**: `prepare`와 `build`만 있다. `begin`·`apply`·`edits.txt`는 없다.

**`prepare`** 출력은 JSON 한 줄 `{"dir", "stage1_prompt", "outline", "pick", "stages": [{"nickname", "kind"}]}` 뒤에, 구체화하는 노드마다 다음 블록이다.

```text
===== <id> · 책임: <책임 한 줄 또는 "없음"> · 단위 <k>개 =====
--- 단위 1: <멤버·문장 이름들>
<범위 기준 줄 번호>| <원본 줄>
…
```

1단계 프롬프트의 구조 뷰에는 `click`으로 시작하는 줄이 없다.

**`outline.json`**(`<dir>/work/outline.json`): 구체화하는 노드마다 `{"placeholders": [k개 문장], "folds": [{"from", "to", "text"}]}`. `folds`는 생략할 수 있다.

**`build`** 거부(종료 코드 2, 한 줄 이유): 1단계 파일이나 `outline.json`이 없음, 노드 항목이 없음, 자리표시자 수가 단위 수와 다름, 빈 자리표시자, 책임 한 줄과 같은 자리표시자(앞뒤 공백·마침표 무시), 접기가 한 멤버의 본문 밖으로 걸치거나 그 멤버의 첫 줄을 포함하거나 서로 겹침, 빈 접기 문장. 모두 펼친 장면이 원본과 다르거나 원본이 바뀌었으면 종료 코드 3이다.

**장면**: 윤곽은 선언 머리(노드 자신의 주석·어노테이션 포함, 쓰이지 않은 매개변수는 `...` 한 줄)와 단위별 `⟨자리표시자⟩`다. k번째 펼치기는 1~k번째 단위의 줄을 원본 그대로(접기는 그 단위에서 `⟨text⟩` 한 줄) 보이고 나머지 단위는 자리표시자로 둔다. 빈 줄은 원본에서 두 항목 사이에 빈 줄이 있을 때만 둔다. 원본 장면은 원본 범위 그대로이며, 마지막 펼치기와 같으면 두지 않는다. prose는 fence 없는 문단, 코드 장면은 원본 언어의 fence(프로필의 `fence` — `kotlin`, `java`, `typescript`, `python` 등, 프로필이 없으면 소문자 확장자 — S10, S11), diff는 연속한 코드 장면끼리다. 펼치기 장면의 제목은 `<k>단계: <별명> <i>/<n> — <자리표시자> (<k>/<전체>)`이다. 노드 제목 아래 책임 한 줄은 그대로다.

# 2026-11-16 학습 장면 계약 (초기 계약보다 우선)

정의의 선택 항목은 `- 표현: prose|code`, `- 반복: dependency`다. CLI·작업 경로는 유지한다. 첫 장면은 상황 문단 하나인 prose 장면이며, 그다음 첫 code 장면의 작업 파일은 `begin`이 `이름 {`·`}`로 시작시킨다. 반복은 직접 화살표 순서로 확장하며 기본 별명으로 숨긴다. `prepare`는 단계별 `nickname/kind/targets`를 출력하고 `begin`도 이 필드를 출력한다. 대상 없는 노드는 이전 코드를 복사하고 화면에서는 해당 장면을 생략한다. prose는 fence 없이 이스케이프한 문단으로, code는 Kotlin fence로 보인다. 제목 아래에 질문 문구는 붙이지 않는다. 숨긴 prose는 코드에 합치지 않는다. 최종 번호·검증은 노드별이며 원본 없는 노드도 구조 뷰만으로 작성 가능한 앞 장면을 보인다. 기존 manifest는 새 필드 부재를 code로 취급한다.

# 2026-11-23 변화 0단계 계약 (위 계약에 더함)

- `prepare <view> [...] [--base=<rev> [--head=<rev>]]`: `--head`는 `--base`와만 쓴다. `--base`가 없으면 출력과 작업 폴더가 지금과 같다. `--base`가 있으면 `manifest.compare = {"base": <짧은 해시>, "head": <짧은 해시 또는 null>}`이고, 노드마다 `change`(`changed`·`removed`·`added`·`same`, 변경 전을 읽지 못한 노드는 `null`)를 둔다. `changed` 노드는 `work/before/<id>.kt`를 갖는다. `removed` 노드의 `work/original/<id>.kt`는 변경 전 범위이고, 스코프 목록에 나온다. 읽지 못한 것은 exit 2가 아니라 `notices`에 `🕘 0단계를 붙이지 못함: <이유>` 한 줄씩 남긴다.

- `build <dir>`: `changed` 노드마다 0단계를 만들고 두 복원을 확인한다. 다르면 exit 3이다. 출력 JSON은 그대로다.

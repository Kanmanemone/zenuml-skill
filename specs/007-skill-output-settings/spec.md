**Feature Branch**: `007-skill-output-settings`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "generating-architecture-views에서 커스텀 설정을 하게 하고싶어. 가령, Responsibility, Collaboration 각각의 내용을 접은 글 박스 안에 넣는 유무같은거. 그 설정 파일을 json 파일로 만들어서 사용자가 직접 조작할 수 있게. 그리고 SKILL.md에서는 그걸 읽어서 적용하는 거지. 마찬가지로 generating-zenuml-diagrams도 같은 방식으로 — 접는 글 박스 외에 적당한 옵션이 있으면 제안. (추가 요청) exporting-markdown-diagrams도 그렇게."

## Clarifications

### Session 2026-11-13

- Q: 앞으로 옵션이 계속 늘어날 때, 옵션 하나를 추가하려면 무엇을 고쳐야 하는가? → A: 변경에 강한 구조로 만든다. 옵션 하나를 추가할 때 그 스킬 안에서 고칠 곳은 옵션 정의 한 곳(키, 허용 값, 기본값, 설명)과 그 옵션이 산출물에 미치는 실제 동작 규칙뿐이어야 한다. 설정 읽기·검증·기본값 대체·안내 같은 공통 처리는 옵션 정의를 근거로 동작하므로 옵션이 늘어도 고치지 않는다. 기존 사용자 설정 파일은 새 옵션이 추가돼도 그대로 동작해야 하며, 빠진 키는 조용히 기본값을 쓴다(FR-016~FR-019, SC-006).
- Q: 접은 글 상자를 쓸 때, 미리보기를 처음 열었을 때 접혀 있을지 펼쳐져 있을지도 설정할 수 있게 하는가? 그리고 설정 파일은 어떤 언어로 쓰는가? → A: 둘 다 정한다. 초기 상태는 미리보기가 아니라 파일에 적힌 표준 속성으로 정해지므로 `collapsed`(처음 접힘)와 `expanded`(처음 펼침)를 구분한다. 설정 파일의 키와 값은 영어로만 쓰고, 각 옵션 위에 한국어 주석으로 의미·허용 값·기본값을 설명하므로 설정 파일은 주석을 허용하는 JSON이어야 한다(FR-020, SC-007).
- Q: 어떤 옵션을 넣는가? 섹션을 아예 그리지 않는 선택지, 설정 파일의 계층, PDF에서의 접은 글 처리는 어떻게 하는가? → A: (1) 실제 SKILL.md·스크립트에 근거가 있는 것만 넣는다 — 사용자가 요청한 Responsibility·Collaboration 표시 방식과, exporting의 기존 고정값·질문(PDF 레이아웃, PNG 배율, 산출 폴더 이름)뿐이다. `generating-zenuml-diagrams`는 근거가 확실한 옵션이 아직 없으므로 설정 파일과 옵션 정의의 틀만 두고 옵션은 비워 둔다. (2) 표시 방식에 섹션을 그리지 않는 `hidden`을 더해 `hidden` / `plain` / `collapsed` / `expanded` 네 값 하나로 고른다 — "그리느냐"와 "어떻게 그리느냐"를 두 키로 나누면 의미 없는 조합이 생기므로 나누지 않는다. (3) 설정 파일은 섹션(또는 기능) 단위로 묶어 계층을 만들고, 그 안에 옵션 키를 둔다(예: `responsibility.display`). (4) 문서 전체 PDF에서는 접은 글 상자를 초기 상태와 상관없이 항상 펼친 상태로 담는다 — 옵션이 아니라 고정 동작이다(FR-008~FR-011, FR-015).
- Q: 사용자가 옵션 값을 고를 때 agent의 토큰 소모(속도)에 어떤 영향이 있는지도 설정 파일에서 알 수 있게 하는가? → A: 그렇다. 각 옵션의 한국어 주석에 값마다 토큰 소모 영향을 짧은 정성적 표시로 함께 적는다. 표시는 기본값 대비 상대적인 영향을 나타내는 정해진 단계 중 하나를 쓰고, 실제 동작에 근거해야 한다(FR-016, FR-018, FR-020 개정, SC-007 개정).
- Q: Dependency 다이어그램의 렌더러를 설정으로 고정할 수 있게 하는가? → A: 그렇다. `generating-architecture-views`에 `dependency.renderer` 옵션을 두어 `default`(렌더러 지정을 넣지 않음 — Mermaid flowchart의 기본 레이아웃 엔진인 dagre로 그려짐, 기본값)와 `elk` 중에서 고른다. 근거는 003 FR-007b의 요청 단위 렌더러 지정이다. 요청 문장에서 렌더러를 직접 밝히면 그 요청에 한해 설정보다 우선한다. 토큰 소모 영향은 두 값 모두 "토큰 소모 영향 거의 없음"이다(FR-011b).
- Q: 산출물·로그의 저장 위치도 설정 파일에 명시하는가? → A: 그렇다. `generating-zenuml-diagrams`의 피드백 로그 저장 위치(`log.directory`, 프로젝트 루트 기준, 기본값 `./.zenuml/log`)와 `exporting-markdown-diagrams`의 산출물 저장 위치(`output.directory`, 원본 파일이 있는 디렉터리 기준, 기본값 `./exports`)를 상대 경로 표기법으로 적는다. 기본값은 지금 위치와 같다. 이로써 `exporting-markdown-diagrams`의 "산출 폴더 이름" 옵션은 저장 위치 옵션으로 바뀌고, `generating-zenuml-diagrams`는 이 옵션 하나를 갖게 된다(FR-014, FR-015c 개정·신설).
- Q: `exporting-markdown-diagrams`가 빠진 정보를 선택지 질문으로 물을지도 설정하는가? 질문할 때 기본값을 표시하는가? → A: 둘 다 설정으로 정한다. `questions.enabled`(기본 `true` — 지금처럼 물음)로 질문 여부를 고르고, 형식·범위·PDF 레이아웃 각각의 기본값을 `defaults.format`, `defaults.scope`, `defaults.pdfLayout`으로 정한다(배포 초기값은 모두 `none` — 기본값 없음, 지금 동작과 같음). 질문을 켜 두면, 설정된 기본값과 같은 선택지의 문자열 끝에 " (기본값)"을 붙인다 — 어느 선택지에 붙을지는 고정이 아니라 설정 값으로 정해진다. 질문을 끄면 빠진 정보를 설정된 기본값으로 묻지 않고 채우되, 기본값이 `none`인 항목만은 그 항목에 한해 여전히 묻는다. 이에 따라 옛 "PDF 레이아웃 기본값(매번 묻기/1페이지/인쇄 규격)" 옵션은 `defaults.pdfLayout`으로 대체된다(FR-013 개정, FR-013b 신설).
- Q: 배포되는 설정 파일의 초기값은 누가 정하는가? → A: 사용자가 항목별로 직접 지정한다. 세 스킬의 구현이 모두 끝난 뒤 모든 옵션의 초기값을 한꺼번에 사용자에게 확인한다. 그때까지 이 spec에 적힌 기본값은 잠정값이며, 잠정값은 기능 도입 전 동작과 같게 둔다(FR-003 개정).
- Q: Dependency 다이어그램의 설정 표기가 `%%{init}%%`에서 YAML frontmatter `config`로 바뀐 뒤(003, 2026-11-13), `dependency.renderer`가 `elk`일 때 렌더러 지정은 어디에 들어가는가? → A: `config.flowchart.defaultRenderer`에 `elk`로 들어간다. 동작(설정·요청 우선순위)은 그대로다(FR-011b, US1/AC5 문구 개정).
- Q: 접은 글 상자의 요약 줄에 섹션 이름을 쓰면 바로 위 헤딩과 단어가 겹친다. 요약 줄을 무엇으로 쓰는가? → A: 고정 문구 `Details`로 쓴다. HTML이 요약 줄이 없을 때 쓰는 기본값과 같은 영어 관례이고, 열림·닫힘 상태와 무관해 어색하지 않다. 섹션 헤딩은 상자 밖에 그대로 두어 개요·앵커를 유지한다(FR-009, Key Entities "접은 글 상자" 개정).
- Q: `dependency.renderer`의 배포 초기값을 무엇으로 하는가? → A: `elk`로 바꾼다(FR-011b 개정, 옵션 정의 기본값과 `settings.jsonc` 값 모두). VS Code 내장 Mermaid 번들(12 계열)은 기본 설정에 `layout: "elk"`가 들어 있어 레이아웃을 지정하지 않아도 이미 ELK로 그리는 반면, PNG/PDF 내보내기 스크립트의 mermaid 11.17은 지정이 없으면 dagre로 그린다. elk를 기본으로 두면 `config.layout: elk`가 늘 들어가 미리보기와 내보내기가 같은 배치가 된다. `default`의 의미는 "지정하지 않음 — 보는 곳의 기본 레이아웃을 따름"으로 정정한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 구조 뷰의 Responsibility·Collaboration 표시 방식 고르기 (Priority: P1)

사용자는 `generating-architecture-views` 스킬 디렉터리에 있는 설정 파일을 직접 열어 Responsibility와 Collaboration 각각의 표시 방식을 고른다: 그리지 않음(`hidden`), 상자 없이 지금처럼(`plain`), 접은 글 상자에 넣고 처음엔 접힘(`collapsed`), 접은 글 상자에 넣고 처음엔 펼침(`expanded`). 이후 구조 뷰를 생성·재생성하면 고른 방식대로 나온다. 긴 구조 뷰에서 Dependency를 먼저 보고 필요한 섹션만 펼쳐 보거나, 필요 없는 섹션은 아예 만들지 않게 할 수 있다.

**Why this priority**: 사용자가 직접 요청한 핵심 옵션이며, 설정 파일을 읽어 적용하는 공통 메커니즘이 이 스토리로 처음 검증된다.

**Independent Test**: 설정 파일에서 두 옵션을 각각 네 값으로 바꿔 가며 같은 설명으로 구조 뷰를 생성해, 섹션별로 고른 방식대로 나오는지, Dependency와 `plain` 섹션은 지금과 똑같이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Responsibility만 `collapsed`로 정한 설정, **When** 사용자가 구조 뷰를 요청하면, **Then** `### Responsibility` 헤딩 아래 내용 전체가 처음엔 접힌 상자 하나에 들어가고, Dependency와 Collaboration은 상자 없이 나온다.
2. **Given** Responsibility는 `collapsed`, Collaboration은 `expanded`로 정한 설정, **When** 구조 뷰가 생성되어 미리보기로 열면, **Then** 두 섹션이 각각 별도 상자에 들어가 Responsibility는 접힌 채로, Collaboration은 펼쳐진 채로 보이며, 어느 상자든 펼친 내용은 `plain`일 때와 같다(항목, 링크, 볼드 표기).
3. **Given** Responsibility를 `hidden`으로 정한 설정, **When** 구조 뷰가 생성되면, **Then** 산출 파일에 `### Responsibility` 헤딩과 내용이 모두 없고 Dependency 다음에 곧바로 Collaboration이 온다. 스킬은 Responsibility 내용을 만들지 않는다.
4. **Given** 설정 파일이 없거나 두 옵션이 모두 `plain`인 상태, **When** 구조 뷰가 생성되면, **Then** 산출물은 이 기능 도입 전과 똑같다.
5. **Given** `dependency.renderer`를 `elk`로 정한 설정, **When** 사용자가 렌더러를 말하지 않고 구조 뷰를 요청하면, **Then** Dependency 다이어그램의 YAML 설정(`config.layout`)에 elk 렌더러 지정이 들어간다. `default`로 정하면 렌더러 지정이 들어가지 않고, 요청에서 다른 렌더러를 직접 밝히면 그 요청에서는 요청한 렌더러가 쓰인다.
6. **Given** 이미 생성된 구조 뷰가 있는 상태에서 사용자가 설정을 바꾼 뒤, **When** 그 구조 뷰의 재생성을 요청하면, **Then** 새 산출물에 바뀐 설정이 적용된다(설정을 바꾸기만 해서는 기존 파일이 고쳐지지 않는다).

### User Story 2 - 내보내기 기본값을 설정으로 고정하기 (Priority: P2)

사용자는 `exporting-markdown-diagrams` 스킬 디렉터리의 설정 파일로 내보내기 방식을 정한다: 빠진 정보를 선택지 질문으로 물을지, 형식·범위·문서 전체 PDF 레이아웃 각각의 기본값, PNG 해상도 배율, 산출물 저장 위치(원본 파일 기준 상대 경로). 질문을 켜 두면 기본값으로 정한 선택지에 " (기본값)"이 붙어 보이고, 끄면 묻지 않고 기본값으로 진행한다. 변환은 지금처럼 번들 스크립트가 수행하며, 스크립트가 설정 값을 읽어 결정적으로 적용한다. 또한 문서 전체 PDF는 접은 글 상자를 항상 펼친 상태로 담는다.

**Why this priority**: 사용자가 추가로 요청한 확장이다. 세 옵션 모두 지금 스크립트에 고정돼 있거나 매번 묻는 값을 설정으로 옮긴 것이고, PDF 펼침은 User Story 1의 접은 글이 PDF에서 내용을 가리지 않게 하는 짝이다.

**Independent Test**: 각 설정 값을 바꿔 같은 마크다운 파일을 내보내, 레이아웃 질문 생략 여부, PNG 픽셀 크기, 산출물 저장 위치가 설정대로 바뀌는지, 접은 상자가 있는 파일의 PDF에서 상자 내용이 모두 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `questions.enabled`가 `true`이고 `defaults.format`이 `png`인 설정, **When** 사용자가 형식을 밝히지 않고 변환을 요청하면, **Then** 형식 질문의 선택지가 `SVG`, `PNG (기본값)`, `PDF`로 보인다. `defaults.format`을 `svg`로 바꾸면 `SVG (기본값)`이 되고, `none`이면 어느 선택지에도 붙지 않는다.
1b. **Given** `questions.enabled`가 `false`이고 `defaults.scope`가 `document`, `defaults.pdfLayout`이 `single`인 설정, **When** 사용자가 형식·범위·레이아웃을 말하지 않고 "이거 변환해줘"라고 하면, **Then** 스킬은 아무것도 묻지 않고 문서 전체를 1페이지 단일 PDF로 만든다. 사용자가 요청에서 직접 밝힌 값은 설정보다 우선한다.
1c. **Given** `questions.enabled`가 `false`이고 `defaults.format`이 `none`인 설정, **When** 범위는 `diagram`으로 정해졌지만 형식이 밝혀지지 않은 요청이면, **Then** 스킬은 형식 질문 하나만 묻는다(채울 기본값이 없으므로).
2. **Given** PNG 배율을 2로 정한 설정, **When** 다이어그램을 PNG로 내보내면, **Then** 결과 이미지의 픽셀 크기가 다이어그램 크기의 2배가 된다.
3. **Given** 산출물 저장 위치를 `./out`으로 정한 설정, **When** 무엇이든 내보내면, **Then** 결과물이 원본 파일과 같은 디렉터리 아래 `out/` 폴더에 모인다. `../exports`처럼 정하면 원본 디렉터리의 한 단계 위 `exports/` 폴더에 모인다.
4. **Given** Responsibility가 `collapsed` 상자에 들어간 구조 뷰 파일, **When** 그 파일을 문서 전체 PDF로 내보내면, **Then** PDF에 Responsibility 내용이 펼쳐진 상태로 담긴다. 원본 파일은 바뀌지 않는다.

### User Story 3 - 시퀀스 다이어그램 피드백 로그 저장 위치 정하기 (Priority: P3)

사용자는 `generating-zenuml-diagrams` 스킬 디렉터리의 설정 파일로 피드백 로그가 저장될 위치를 프로젝트 루트 기준 상대 경로로 정한다(기본값 `./.zenuml/log` — 지금 위치). 옵션 구조는 다른 두 스킬과 같으며, 나중에 옵션이 생기면 같은 절차(FR-018)로 추가한다.

**Why this priority**: 사용자가 요청한 옵션 하나만 있는 가장 작은 스토리다.

**Independent Test**: 로그 저장 위치를 기본값과 다른 상대 경로로 바꿔 다이어그램을 생성·재생성해, 로그가 그 위치에 만들어지고 이어 쓰이는지, 다이어그램 산출물 자체는 기능 도입 전과 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 배포된 그대로의 설정 파일, **When** 다이어그램이 생성되면, **Then** 산출물과 로그 위치(`.zenuml/log/<slug>.md`)가 이 기능 도입 전과 똑같다.
2. **Given** 로그 저장 위치를 `./docs/diagram-logs`로 정한 설정, **When** 다이어그램이 생성·재생성되면, **Then** 로그가 프로젝트 루트 아래 `docs/diagram-logs/<slug>.md`에 만들어지고 이어 쓰이며, 폴더가 없으면 새로 만든다.
3. **Given** 사용자가 설정 파일에 정의되지 않은 키를 적은 상태, **When** 다이어그램이 생성되면, **Then** 다이어그램은 그대로 생성되고 채팅 응답에 그 키를 무시했다는 한 줄 안내가 붙는다.

---

### Edge Cases

- 설정 파일이 없으면 모든 옵션에 기본값을 쓰며, 산출물은 이 기능 도입 전과 같다. 이 경우 따로 알리지 않는다.
- 설정 파일이 주석 허용 JSON으로도 읽히지 않으면, 모든 옵션에 기본값을 쓰고 작업은 그대로 진행한 뒤, 채팅 응답에 어떤 파일을 읽지 못했는지 한 줄로 알린다.
- 특정 키의 값이 허용되지 않는 형식이거나 범위를 벗어나면(예: PNG 배율에 문자열이나 0 이하, 표시 방식에 정의되지 않은 값), 그 키만 기본값으로 대체하고 나머지 키는 그대로 적용한 뒤, 어떤 키를 기본값으로 대체했는지 한 줄로 알린다.
- 설정 파일에 알 수 없는 키가 있으면(오타, 없어지거나 이름이 바뀐 옵션 등) 그 키는 무시하고, 무시한 키 이름을 한 줄로 알린다.
- 스킬이 새 옵션을 추가한 뒤에도 사용자의 기존 설정 파일에 그 키가 없으면, 그 옵션은 조용히 기본값을 쓴다(안내 없음). 사용자가 직접 적은 다른 키의 값은 그대로 유지된다.
- 사용자가 요청에서 설정과 다른 형식을 직접 밝히면(예: `collapsed`로 정했는데 "이번엔 상자 없이 줘", `hidden`인데 "이번엔 Responsibility도 보여줘"), 그 요청에 한해 사용자의 말이 설정보다 우선하며 설정 파일 자체는 바뀌지 않는다.
- Responsibility와 Collaboration을 모두 `hidden`으로 정하면 산출 파일에는 Dependency 섹션만 남는다.
- 저장 위치를 `.gitignore`가 무시하지 않는 곳으로 바꾸면, 그 위치에 생기는 산출물·로그는 git에서 추적 대상 후보로 보인다. 스킬은 `.gitignore`를 고치지 않으며, 무시 처리는 사용자가 정한다.
- 파일 저장이 불가능한 환경에서는 산출물을 채팅에 직접 넣는 기존 대체 동작을 따르되, 표시 방식 옵션은 그 텍스트에도 똑같이 적용한다.

## Requirements *(mandatory)*

### Functional Requirements

**공통 설정 메커니즘**

- **FR-001**: 세 스킬(`generating-architecture-views`, `generating-zenuml-diagrams`, `exporting-markdown-diagrams`)은 각자 자기 스킬 디렉터리 안에 사용자가 직접 편집할 수 있는 설정 파일을 하나씩 가져야 하며, 그 파일에는 그 스킬의 모든 옵션이 기본값으로 미리 적혀 있어야 한다. 파일 형식은 FR-020을 따른다.
- **FR-002**: 각 스킬은 실행할 때마다 자기 설정 파일을 새로 읽어 그 실행의 산출물에 적용해야 한다. 이전 실행에서 읽은 값을 기억해 재사용해서는 안 된다.
- **FR-003**: 배포되는 설정 파일의 초기값과 옵션 정의의 기본값(키가 없을 때 쓰는 값)은 같아야 하며, 그 값은 사용자가 항목별로 지정한다 — 세 스킬의 구현이 모두 끝난 뒤 모든 옵션의 초기값을 한꺼번에 사용자에게 확인해 확정한다. 확정 전까지 이 spec의 FR에 적힌 기본값은 잠정값이며, 잠정값은 기능 도입 전 동작과 같다.
- **FR-004**: 설정 파일이 없으면 스킬은 모든 옵션에 기본값을 쓰고 아무것도 알리지 않아야 한다.
- **FR-005**: 설정 파일을 읽을 수 없거나, 어떤 키의 값이 허용되지 않거나, 알 수 없는 키가 있으면, 스킬은 해당 부분만 기본값으로 대체(또는 무시)하고 작업을 끝까지 진행한 뒤, 채팅 응답에 대상 파일과 키를 밝히는 한 줄 안내를 덧붙여야 한다. 이 안내는 산출 파일에는 넣지 않으며, 기존 "산출물에는 실제 내용만" 규칙(003 FR-032, 001 FR-012)의 허용 예외로 추가된다.
- **FR-006**: 사용자가 요청 문장에서 설정과 다른 형식을 직접 밝히면, 그 요청에 한해 사용자의 말이 설정보다 우선해야 한다. 스킬은 설정 파일을 직접 고쳐서는 안 된다.
- **FR-007**: 설정을 바꾼다고 이미 만들어진 산출물이 자동으로 고쳐져서는 안 된다. 바뀐 설정은 다음 생성·재생성·내보내기부터 적용된다.

**generating-architecture-views 옵션**

- **FR-008**: 설정은 Responsibility와 Collaboration 각각의 표시 방식(`display`)을 `hidden`(그리지 않음), `plain`(상자 없음), `collapsed`(접은 글 상자, 처음 접힘), `expanded`(접은 글 상자, 처음 펼침) 중 하나로 독립적으로 고를 수 있어야 한다(기본: 둘 다 `plain`).
- **FR-009**: `collapsed`나 `expanded`인 섹션은 섹션 헤딩(`### Responsibility` / `### Collaboration`)을 상자 밖에 그대로 두고, 그 아래 내용 전체를 상자 하나에 넣어야 한다. 미리보기를 처음 열었을 때 `collapsed`는 접힌 상태로, `expanded`는 펼쳐진 상태로 보여야 하며, 어느 쪽이든 사용자가 클릭해 접고 펼 수 있어야 한다. 상자의 요약 줄(▶ 옆 문구)은 섹션과 상태에 관계없이 고정 문구 `Details`로 쓴다 — 섹션 이름은 상자 밖 헤딩에만 나온다. 상자를 펼쳤을 때의 내용(항목, 하이퍼링크, 볼드 표기, 하위 헤딩 순서)은 `plain`일 때와 같아야 한다.
- **FR-010**: `hidden`인 섹션은 헤딩과 내용 모두 산출 파일에 넣지 않아야 하며, 스킬은 그 섹션의 내용을 만들거나 그 섹션만을 위한 자기검증을 하지 않아야 한다. 나머지 섹션의 순서(Dependency → Responsibility → Collaboration)는 유지된다.
- **FR-011**: Dependency 섹션(캡션과 다이어그램)은 이 옵션들과 상관없이 항상 상자 없이 나와야 한다.
- **FR-011b**: 설정은 Dependency 다이어그램의 렌더러(`dependency.renderer`)를 `default`(렌더러 지정을 넣지 않음 — 보는 곳의 Mermaid 기본 레이아웃을 따른다. VS Code 내장 Mermaid와 내보내기 스크립트 모두 Mermaid 12라 현재는 elk — 004 FR-017로 내보내기를 12로 올리기 전 mermaid 11.17은 dagre였다)와 `elk` 중에서 고를 수 있어야 한다(기본: `elk`, 사용자 확정 2026-11-13). `elk`이면 매 생성·재생성마다 003 FR-007b와 같은 방식으로 YAML 설정의 `config.layout`에 elk를 넣는다(`config.flowchart.defaultRenderer`는 VS Code 내장 Mermaid가 무시하므로 쓰지 않는다 — 003 FR-007b, 2026-11-13). 요청 문장이 렌더러를 직접 밝히면 그 요청에 한해 요청 값이 설정보다 우선한다(FR-006, 003 FR-007b).
- **FR-012**: 피드백 로그의 Response에는 산출 파일에 실제로 쓴 내용(상자 포함, `hidden` 섹션 제외)이 그대로 기록돼야 한다.

**exporting-markdown-diagrams 옵션과 동작**

- **FR-013**: 설정은 형식·범위·문서 전체 PDF 레이아웃 각각의 기본값을 정할 수 있어야 한다 — `defaults.format`(`none`/`svg`/`png`/`pdf`), `defaults.scope`(`none`/`diagram`/`document`), `defaults.pdfLayout`(`none`/`single`/`paginated`). 배포 초기값은 모두 `none`(기본값 없음)이다. 요청 문장이 직접 밝힌 값은 언제나 기본값보다 우선한다.
- **FR-013b**: 설정은 빠진 정보를 선택지 질문으로 물을지(`questions.enabled`, 기본 `true`)를 정할 수 있어야 한다. `true`이면 지금처럼 빠진 정보만 묻되, 각 질문에서 FR-013의 기본값과 같은 선택지의 문자열 끝에 " (기본값)"을 붙인다 — 붙는 위치는 설정 값으로만 정해지며 고정된 선택지가 없고, 기본값이 `none`이면 어느 선택지에도 붙이지 않는다. `false`이면 빠진 정보를 묻지 않고 기본값으로 채우며, 기본값이 `none`이라 채울 수 없는 항목만 그 항목에 한해 묻는다. 기존 질문 규칙(빠진 형식·범위·레이아웃은 한 번에 함께 묻기, 문서 전체면 형식은 PDF·PNG 중에서, 다이어그램만이면 레이아웃 답은 무시 — 004 FR-003·FR-014, 008)은 그대로다.
- **FR-014**: 설정은 PNG 해상도 배율을 양수로 정할 수 있어야 하며(기본: 3), 산출물 저장 위치(`output.directory`)를 원본 파일이 있는 디렉터리 기준 상대 경로로 정할 수 있어야 한다(기본: `./exports` — 지금 위치). 저장 위치가 없으면 새로 만든다. 절대 경로나 경로로 해석할 수 없는 값은 허용되지 않는 값으로 보고 FR-005를 따른다.
- **FR-015**: 문서 전체 PDF는 원본의 접은 글 상자를 초기 상태(`collapsed`/`expanded`)와 상관없이 모두 펼친 상태로 담아, 상자 안 내용이 빠짐없이 보이게 해야 한다. 이는 설정 옵션이 아니라 고정 동작이며, 원본 마크다운 파일은 바뀌지 않는다.
- **FR-015b**: 이 스킬의 설정 값과 FR-015의 동작은 번들 스크립트가 직접 적용해야 한다. 변환 결과가 LLM 판단에 의존하지 않는다는 기존 원칙(004 spec)은 그대로 유지된다. 레이아웃 질문을 생략할지 같은 대화 흐름 판단만 SKILL.md가 설정을 읽어 결정한다.

**generating-zenuml-diagrams 옵션**

- **FR-015c**: 설정은 피드백 로그 저장 위치(`log.directory`)를 프로젝트 루트 기준 상대 경로로 정할 수 있어야 한다(기본: `./.zenuml/log` — 지금 위치). 로그 파일 이름 규칙(`<slug>.md`)과 append-only 동작은 그대로이며, 위치가 없으면 새로 만든다. 위치를 바꿔도 이전 위치의 기존 로그는 옮기거나 지우지 않는다. 절대 경로나 경로로 해석할 수 없는 값은 FR-005를 따른다.

**옵션 확장 구조**

- **FR-016**: 각 스킬은 자기 옵션 전체를 한 곳에 모은 옵션 정의를 가져야 한다. 옵션 하나의 정의는 키(소속 묶음 포함), 허용 값(정해진 선택지, 수의 범위, 문자열 규칙 등), 기본값, 사용자를 위한 한 줄 설명, 값별 토큰 소모 영향(FR-020)으로 이뤄진다. 이 정의가 그 스킬 옵션의 유일한 기준이며, 같은 정보가 다른 곳에 따로 적혀 서로 어긋나서는 안 된다.
- **FR-017**: 설정 읽기, 값 검증, 기본값 대체, 알 수 없는 키 처리, 안내 문구 생성(FR-002, FR-004, FR-005)은 옵션 정의만 근거로 동작해야 한다. 옵션을 추가·삭제·변경해도 이 공통 처리 규칙이나 코드는 고칠 필요가 없어야 한다.
- **FR-018**: 새 옵션을 추가할 때 그 스킬 안에서 고쳐야 하는 곳은 (a) 옵션 정의에 항목 하나를 더하는 것, (b) 그 옵션이 산출물에 미치는 동작 규칙을 해당 생성·변환 단계에 더하는 것, (c) 배포되는 설정 파일에 새 키를 기본값과 FR-020의 한국어 주석(토큰 소모 영향 포함)과 함께 더하는 것뿐이어야 한다.
- **FR-019**: 기존 사용자 설정 파일은 스킬에 새 옵션이 추가되거나 옵션 정의가 바뀌어도 고치지 않고 계속 쓸 수 있어야 한다. 빠진 키는 기본값을 쓰고(안내 없음), 더는 정의되지 않은 키는 FR-005에 따라 무시하고 안내한다.
- **FR-020**: 설정 파일은 섹션이나 기능 단위의 묶음 아래에 옵션 키를 두는 계층 구조여야 한다(예: `responsibility` 묶음 아래 `display`, `pdf` 묶음 아래 `layout`). 키와 값은 영어로만 쓰고, 배포되는 설정 파일에는 각 옵션 바로 위에 한국어 주석으로 그 옵션의 의미, 허용 값 각각의 뜻, 기본값을 적어야 한다. 따라서 설정 파일은 주석을 허용하는 JSON 형식이어야 하며, 세 스킬의 설정 읽기는 주석이 있어도 정상적으로 읽어야 한다. 주석의 설명은 옵션 정의(FR-016)와 어긋나서는 안 되며, 사용자가 주석을 지우거나 고쳐도 설정 값 해석에는 영향이 없어야 한다. 주석에는 값마다 agent 토큰 소모에 미치는 영향을 기본값 대비 정해진 단계 — "토큰 소모 줄어듦", "토큰 소모 영향 거의 없음", "토큰 소모 늘어남", "토큰 소모 큼" — 중 하나로 함께 적어야 한다. 이 표시는 그 값이 실제로 바꾸는 동작에 근거해야 한다(예: 섹션을 아예 만들지 않는 `hidden`은 "토큰 소모 줄어듦", 내용은 같고 상자만 씌우는 `collapsed`·`expanded`는 "토큰 소모 영향 거의 없음", 번들 스크립트가 처리하는 PNG 배율·저장 위치은 "토큰 소모 영향 거의 없음").

### Key Entities *(include if feature involves data)*

- **스킬 설정 파일**: 스킬마다 하나씩 그 스킬 디렉터리 안에 있는, 주석을 허용하는 JSON 문서. 섹션·기능 단위 묶음 아래 옵션 키를 둔다. 사용자가 직접 편집하며, 처음부터 모든 옵션이 기본값으로 적혀 있다. 키와 값은 영어, 각 옵션 위의 설명 주석은 한국어다(FR-020).
- **옵션 정의**: 스킬마다 하나씩 있는, 그 스킬 옵션 전체의 유일한 기준. 옵션마다 키(소속 묶음 포함), 허용 값, 기본값, 한 줄 설명, 값별 토큰 소모 영향을 담는다(FR-016). 설정 읽기·검증·안내는 이 정의만 보고 동작한다.
- **설정 옵션**: 옵션 정의의 항목 하나. 현재 목록은 `generating-architecture-views`의 `responsibility.display`·`collaboration.display`(FR-008)와 `dependency.renderer`(FR-011b), `exporting-markdown-diagrams`의 `questions.enabled`, `defaults.format`·`defaults.scope`·`defaults.pdfLayout`, PNG 배율, 산출물 저장 위치(FR-013, FR-013b, FR-014), `generating-zenuml-diagrams`의 피드백 로그 저장 위치(FR-015c)다. 이후 FR-018 절차로 늘어날 수 있다.
- **설정 안내**: 설정 파일을 읽지 못했거나 일부 값을 기본값으로 대체·무시했을 때 채팅 응답에만 붙는 한 줄. 대상 파일과 키를 밝힌다.
- **접은 글 상자**: 마크다운 미리보기에서 클릭해 접고 펼 수 있는 블록. 요약 줄(고정 문구 `Details`)과 내용으로 이뤄지며, 처음 열었을 때의 상태(접힘/펼침)가 파일 안에 적혀 있다. 클릭으로 바꾼 상태는 파일에 저장되지 않으므로 다시 열면 적힌 초기 상태로 돌아간다.

## Success Criteria *(mandatory)*

- **SC-001**: 잠정 기본값 상태에서 설정 파일을 건드리지 않았을 때 세 스킬의 산출물이 이 기능 도입 전과 달라지는 비율이 0%이고, 사용자가 확정한 초기값이 배포 설정 파일과 옵션 정의 양쪽에 똑같이 반영되는 비율이 100%다.
- **SC-002**: 각 옵션을 기본값과 다른 값으로 바꿨을 때, 그 옵션에 해당하는 부분만 달라지고 나머지 산출물은 같은 비율이 100%다(옵션·값별 대표 시나리오 기준).
- **SC-003**: 읽을 수 없는 설정 파일, 잘못된 값, 알 수 없는 키가 있는 상황에서 작업이 중단되는 비율이 0%이고, 그 사실이 채팅에 한 줄로 안내되는 비율이 100%다.
- **SC-004**: 접은 글 상자가 있는 마크다운 파일을 문서 전체 PDF로 내보냈을 때, 상자 안 내용이 PDF에서 빠지는 비율이 0%다.
- **SC-005**: 같은 설정과 같은 입력 파일로 내보내기를 반복했을 때 결과물의 형식(레이아웃, PNG 픽셀 크기, 산출물 저장 위치)이 매번 같은 비율이 100%다.
- **SC-006**: 대표 시나리오로 각 스킬에 시험용 옵션 하나를 추가했을 때, 고친 곳이 FR-018의 세 곳뿐이고 공통 처리 규칙은 한 줄도 바뀌지 않으며, 그 옵션 추가 이전에 만든 사용자 설정 파일이 고치지 않은 채로 오류 안내 없이 동작하는 비율이 100%다.
- **SC-007**: 배포된 설정 파일만 보고, 영어를 모르는 한국어 사용자가 원하는 옵션을 찾아 허용 값 중 하나로 바꿀 수 있는 비율이 100%다(모든 옵션 위에 의미·허용 값·기본값·값별 토큰 소모 영향 주석이 있고, 그 내용이 실제 동작과 일치함).
- **SC-008**: Responsibility나 Collaboration을 `hidden`으로 정했을 때, 그 섹션의 헤딩이나 내용이 산출 파일에 한 줄이라도 남는 비율이 0%다.
- **SC-009**: `questions.enabled`가 `true`일 때, " (기본값)"이 설정된 기본값과 같은 선택지에만 정확히 하나 붙고(기본값이 `none`이면 하나도 없음) 설정 값을 바꾸면 붙는 위치도 따라 바뀌는 비율이 100%이며, `false`일 때 기본값이 있는 항목에 대해 질문이 뜨는 비율이 0%다.

## Assumptions

- **설정 파일 위치**: 각 스킬 디렉터리 안에 둔다. 스킬을 다른 프로젝트에 복사해 쓰면 설정도 함께 따라간다. 저장소에서는 기본값이 적힌 상태로 추적된다.
- **접은 글 상자의 형식**: 마크다운 미리보기(VS Code 기본 미리보기, GitHub)가 접고 펼 수 있게 렌더링하는 표준 HTML 접기 블록을 쓰며, `expanded`는 그 블록의 표준 "처음부터 열림" 속성으로 표현한다. 상자 안의 마크다운이 펼쳤을 때 정상 렌더링되도록 형식을 맞추는 것과, PDF 변환 파이프라인에서 상자를 펼치는 방법은 계획 단계에서 실측으로 확정한다.
- **Dependency는 표시 방식 옵션에서 제외**: 사용자가 Responsibility와 Collaboration만 언급했고, Dependency는 구조 뷰에서 가장 먼저 보여야 할 내용이므로 옵션을 두지 않는다.
- **옵션 선정 기준**: 실제 SKILL.md·스크립트에 근거가 있는 것만 옵션으로 둔다 — 사용자가 직접 요청한 것(표시 방식, 렌더러, 저장 위치, 질문 여부와 기본값 표시), 그리고 지금 스크립트에 고정돼 있거나(PNG 배율, 산출물 저장 위치) 매번 묻는 것(형식·범위·PDF 레이아웃)이다. 기존 동작에 켬/끔만 덧붙인 제안(피드백 로그, 다이어그램 주석, 지어낸 이름 언어, 다이어그램 표시 방식)과 근거가 없는 제안(참가자 종류 표시)은 넣지 않는다. 형식·범위 질문은 요청마다 달라지는 값이므로 설정으로 고정하지 않는다.
- **`hidden`과 계층 구조의 선택 이유**: "그리느냐"(1단계)와 "어떻게 그리느냐"(2단계)를 별도 키로 나누면 "안 그림 + 접힘" 같은 의미 없는 조합이 생기므로, 표시 방식 값 하나에 `hidden`을 포함한다. 계층은 섹션·기능 단위로만 만들어, 이후 섹션별 옵션이 늘면 그 묶음 안에 키를 더한다.
- **우선순위**: 요청 문장 > 설정 파일 > 기본값. 요청 문장의 지정은 그 요청에만 적용되고 저장되지 않는다(003 FR-007b의 렌더러 지정과 같은 원칙).
- **로컬 개인 기본값과의 관계**: CLAUDE.local.md에 둔 "매 요청을 elk로 지정한 것처럼 취급" 같은 개인 지침은 이 설정 파일과 별개로 유지되며, 이 기능이 자동으로 바꾸거나 지우지 않는다. 그 지침은 요청 문장에 elk를 밝힌 것과 같은 효과를 내므로 설정보다 우선한다. 같은 효과를 설정으로 얻으려면 사용자가 `dependency.renderer`를 `elk`로 바꾸고 그 지침을 직접 정리하면 된다.

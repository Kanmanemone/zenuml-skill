**Feature Branch**: `007-skill-output-settings`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 구조 뷰의 Responsibility·Collaboration을 접은 글로 받기 (Priority: P1)

사용자는 `generating-architecture-views` 스킬 디렉터리에 있는 설정 파일을 직접 열어 Responsibility와 Collaboration 각각을 접은 글 박스에 넣을지 켜고 끈다. 이후 구조 뷰를 생성·재생성하면, 켠 섹션은 섹션 헤딩은 그대로 보이고 그 아래 내용 전체가 기본으로 접힌 박스 안에 들어간다. 긴 구조 뷰에서 Dependency 다이어그램을 먼저 보고 필요한 섹션만 펼쳐 볼 수 있다.

**Why this priority**: 사용자가 직접 요청한 핵심 옵션이며, 설정 파일을 읽어 적용하는 공통 메커니즘이 이 스토리로 처음 검증된다.

**Independent Test**: 설정 파일에서 두 옵션을 각각 켠 상태·끈 상태로 바꿔 가며 같은 설명으로 구조 뷰를 생성해, 켠 섹션만 접은 글 박스로 감싸지는지, 끈 섹션과 Dependency는 지금과 똑같이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Responsibility 접기 옵션만 켠 설정, **When** 사용자가 구조 뷰를 요청하면, **Then** `### Responsibility` 헤딩 아래 내용 전체가 접힌 박스 하나에 들어가고, Dependency와 Collaboration은 접히지 않은 채로 나온다.
2. **Given** 두 옵션을 모두 켠 설정, **When** 구조 뷰가 생성되면, **Then** Responsibility와 Collaboration이 각각 별도의 접힌 박스에 들어가고, 박스를 펼치면 접지 않았을 때와 같은 내용(항목, 링크, 볼드 표기)이 그대로 보인다.
3. **Given** 설정 파일이 없거나 두 옵션이 모두 꺼진 상태, **When** 구조 뷰가 생성되면, **Then** 산출물은 이 기능 도입 전과 똑같다.
4. **Given** 이미 생성된 구조 뷰가 있는 상태에서 사용자가 설정을 바꾼 뒤, **When** 그 구조 뷰의 재생성을 요청하면, **Then** 새 산출물에 바뀐 설정이 적용된다(설정을 바꾸기만 해서는 기존 파일이 고쳐지지 않는다).

### User Story 2 - 시퀀스 다이어그램 산출 형식을 설정으로 고르기 (Priority: P2)

사용자는 `generating-zenuml-diagrams` 스킬 디렉터리의 설정 파일로 시퀀스 다이어그램 산출 형식을 고른다: 다이어그램을 접은 글 박스에 넣을지, 참가자 종류 표시(사람·데이터베이스·큐 등)를 쓸지, 다이어그램 안에 주석(노트)을 허용할지, 지어낸 참가자·메서드 이름을 사용자의 언어로 쓸지 영어로 쓸지, 피드백 로그를 남길지.

**Why this priority**: 같은 메커니즘을 두 번째 스킬로 넓히는 스토리다. 사용자가 접은 글 외의 옵션을 제안해 달라고 했으므로, 이 스킬이 이미 하는 판단 중 사람마다 선호가 갈리는 것을 옵션으로 뽑았다.

**Independent Test**: 각 옵션을 하나씩 기본값과 반대로 바꿔 같은 설명으로 다이어그램을 생성해, 바꾼 옵션에 해당하는 부분만 달라지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 다이어그램 접기를 켠 설정, **When** 다이어그램이 생성되면, **Then** 산출 파일의 다이어그램 코드펜스가 접힌 박스 하나에 들어가고, 펼치면 그대로 렌더링된다.
2. **Given** 참가자 종류 표시를 끈 설정과 "사용자가 DB에서 주문을 조회한다"는 설명, **When** 다이어그램이 생성되면, **Then** 어떤 참가자에도 종류 표시가 붙지 않는다. 켠 설정에서는 설명이 종류를 밝힌 참가자(사용자→사람, DB→데이터베이스)에만 붙고, 종류를 밝히지 않은 참가자에는 붙지 않는다.
3. **Given** 주석을 끈 설정, **When** 다이어그램이 생성되면, **Then** 다이어그램 DSL에 주석(노트)이 하나도 없다.
4. **Given** 지어낸 이름의 언어를 영어로 정한 설정과 한국어 설명, **When** 다이어그램이 생성되면, **Then** 실제 코드가 없는 지어낸 참가자·메서드 이름은 영어로 쓰이고, 설명이 인용한 실제 식별자는 원문 그대로 남는다.
5. **Given** 피드백 로그를 끈 설정, **When** 다이어그램이 생성·재생성되면, **Then** 산출 파일만 만들어지거나 갱신되고 로그 파일은 새로 만들어지거나 이어 쓰이지 않는다.

### User Story 3 - 내보내기 기본값을 설정으로 고정하기 (Priority: P3)

사용자는 `exporting-markdown-diagrams` 스킬 디렉터리의 설정 파일로 내보내기 기본값을 고정한다: 문서 전체 PDF의 레이아웃(매번 묻기 / 1페이지 단일 / 표준 인쇄 규격), PNG 해상도 배율, 산출물이 모이는 하위 폴더 이름, 문서 전체 PDF에서 접은 글 박스를 펼친 상태로 담을지. 변환은 지금처럼 번들 스크립트가 수행하며, 스크립트가 설정 값을 읽어 결정적으로 적용한다.

**Why this priority**: 사용자가 추가로 요청한 확장이며, User Story 1·2의 접은 글 옵션이 PDF에서 내용을 가리지 않게 하는 짝 역할도 한다.

**Independent Test**: 각 설정 값을 바꿔 같은 마크다운 파일을 내보내, 레이아웃 질문 생략 여부, PNG 픽셀 크기, 산출 폴더 이름, PDF 안 접은 글 박스의 펼침 상태가 설정대로 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** PDF 레이아웃을 "1페이지 단일"로 정한 설정, **When** 사용자가 문서 전체 PDF 변환을 요청하면서 레이아웃을 말하지 않으면, **Then** 스킬은 레이아웃을 묻지 않고 1페이지 단일 PDF를 만든다. 사용자가 요청에서 레이아웃을 직접 밝히면 설정보다 그 말이 우선한다.
2. **Given** PNG 배율을 2로 정한 설정, **When** 다이어그램을 PNG로 내보내면, **Then** 결과 이미지의 픽셀 크기가 다이어그램 크기의 2배가 된다.
3. **Given** 산출 폴더 이름을 "out"으로 정한 설정, **When** 무엇이든 내보내면, **Then** 결과물이 원본 옆 `out/` 폴더에 모인다.
4. **Given** 접은 글 펼치기를 켠(기본) 설정과 Responsibility가 접힌 구조 뷰 파일, **When** 그 파일을 문서 전체 PDF로 내보내면, **Then** PDF에 Responsibility 내용이 펼쳐진 상태로 담긴다. 끈 설정에서는 원본처럼 접힌 상태로 담긴다.

---

### Edge Cases

- 설정 파일이 없으면 모든 옵션에 기본값을 쓰며, 산출물은 이 기능 도입 전과 같다. 이 경우 따로 알리지 않는다.
- 설정 파일이 JSON으로 읽히지 않으면, 모든 옵션에 기본값을 쓰고 작업은 그대로 진행한 뒤, 채팅 응답에 어떤 파일을 읽지 못했는지 한 줄로 알린다.
- 특정 키의 값이 허용되지 않는 형식이거나 범위를 벗어나면(예: PNG 배율에 문자열이나 0 이하), 그 키만 기본값으로 대체하고 나머지 키는 그대로 적용한 뒤, 어떤 키를 기본값으로 대체했는지 한 줄로 알린다.
- 설정 파일에 알 수 없는 키가 있으면(오타 등) 그 키는 무시하고, 무시한 키 이름을 한 줄로 알린다.
- 사용자가 요청에서 설정과 다른 형식을 직접 밝히면(예: 접기를 켰는데 "이번엔 펼쳐서 줘"), 그 요청에 한해 사용자의 말이 설정보다 우선하며 설정 파일 자체는 바뀌지 않는다.
- 파일 저장이 불가능한 환경에서는 산출물을 채팅에 직접 넣는 기존 대체 동작을 따르되, 접기 옵션은 그 텍스트에도 똑같이 적용한다. 피드백 로그는 원래 이 환경에서 만들지 않으므로 로그 옵션은 영향이 없다.
- 구조 뷰에서 시퀀스 다이어그램으로 이어지는 hand-off 실행에는 `generating-zenuml-diagrams` 자신의 설정이 적용된다. 구조 뷰 설정은 넘어가지 않는다.
- 피드백 로그를 끈 상태에서는 기존 로그 파일이 있어도 지우거나 고치지 않고 그대로 둔다. 다시 켜면 그 파일에 이어서 기록한다.

## Requirements *(mandatory)*

### Functional Requirements

**공통 설정 메커니즘**

- **FR-001**: 세 스킬(`generating-architecture-views`, `generating-zenuml-diagrams`, `exporting-markdown-diagrams`)은 각자 자기 스킬 디렉터리 안에 사용자가 직접 편집할 수 있는 JSON 설정 파일을 하나씩 가져야 하며, 그 파일에는 모든 옵션이 기본값으로 미리 적혀 있어야 한다.
- **FR-002**: 각 스킬은 실행할 때마다 자기 설정 파일을 새로 읽어 그 실행의 산출물에 적용해야 한다. 이전 실행에서 읽은 값을 기억해 재사용해서는 안 된다.
- **FR-003**: 모든 옵션의 기본값은 이 기능 도입 전의 동작과 같아야 한다. 설정 파일을 전혀 건드리지 않은 사용자는 산출물에서 어떤 차이도 느끼지 않아야 한다.
- **FR-004**: 설정 파일이 없으면 스킬은 모든 옵션에 기본값을 쓰고 아무것도 알리지 않아야 한다.
- **FR-005**: 설정 파일을 JSON으로 읽을 수 없거나, 어떤 키의 값이 허용되지 않거나, 알 수 없는 키가 있으면, 스킬은 해당 부분만 기본값으로 대체(또는 무시)하고 작업을 끝까지 진행한 뒤, 채팅 응답에 대상 파일과 키를 밝히는 한 줄 안내를 덧붙여야 한다. 이 안내는 산출 파일에는 넣지 않으며, 기존 "산출물에는 실제 내용만" 규칙(003 FR-032, 001 FR-012)의 허용 예외로 추가된다.
- **FR-006**: 사용자가 요청 문장에서 설정과 다른 형식을 직접 밝히면, 그 요청에 한해 사용자의 말이 설정보다 우선해야 한다. 스킬은 설정 파일을 직접 고쳐서는 안 된다.
- **FR-007**: 설정을 바꾼다고 이미 만들어진 산출물이 자동으로 고쳐져서는 안 된다. 바뀐 설정은 다음 생성·재생성·내보내기부터 적용된다.

**generating-architecture-views 옵션**

- **FR-008**: 설정은 Responsibility 접기와 Collaboration 접기를 각각 독립적으로 켜고 끌 수 있어야 한다(기본: 둘 다 끔).
- **FR-009**: 접기가 켜진 섹션은 섹션 헤딩(`### Responsibility` / `### Collaboration`)을 접힌 박스 밖에 그대로 두고, 그 아래 내용 전체를 기본으로 접힌 박스 하나에 넣어야 한다. 박스의 요약 줄에는 섹션 이름만 쓴다. 박스를 펼쳤을 때의 내용(항목, 하이퍼링크, 볼드 표기, 하위 헤딩 순서)은 접지 않았을 때와 같아야 한다.
- **FR-010**: Dependency 섹션(캡션과 다이어그램)은 이 옵션들과 상관없이 항상 접히지 않은 채로 나와야 한다.
- **FR-011**: 설정은 구조 뷰 피드백 로그 기록을 켜고 끌 수 있어야 한다(기본: 켬). 끄면 산출 파일만 만들거나 갱신하고, 로그 파일은 만들거나 이어 쓰지 않으며, 기존 로그 파일도 건드리지 않는다.
- **FR-012**: 피드백 로그의 Response에는 산출 파일에 실제로 쓴 내용(접은 박스 포함)이 그대로 기록돼야 한다.

**generating-zenuml-diagrams 옵션**

- **FR-013**: 설정은 다이어그램 접기를 켜고 끌 수 있어야 한다(기본: 끔). 켜면 산출 파일의 다이어그램 코드펜스가 기본으로 접힌 박스 하나에 들어가며, 펼치면 그대로 렌더링돼야 한다. 이 박스는 001 FR-012의 "산출 파일은 코드펜스만"의 허용 예외다.
- **FR-014**: 설정은 참가자 종류 표시 사용을 켜고 끌 수 있어야 한다(기본: 켬). 켜면 설명이 종류(사람, 데이터베이스, 큐 등)를 밝힌 참가자에만 종류 표시를 붙이고 밝히지 않은 참가자에는 붙이지 않으며, 끄면 어떤 참가자에도 붙이지 않는다.
- **FR-015**: 설정은 다이어그램 안 주석(노트) 허용을 켜고 끌 수 있어야 한다(기본: 켬). 켜면 지금처럼 설명이 실제로 언급한 내용에 한해 주석을 쓸 수 있고, 끄면 주석을 하나도 쓰지 않는다.
- **FR-016**: 설정은 지어낸 참가자·메서드 이름의 언어를 "사용자 언어"와 "영어" 중에서 고를 수 있어야 한다(기본: 사용자 언어). 어느 쪽이든 설명이 인용한 실제 코드 식별자는 원문 그대로 둔다.
- **FR-017**: 설정은 다이어그램 피드백 로그 기록을 켜고 끌 수 있어야 하며(기본: 켬), 꺼졌을 때의 동작은 FR-011과 같다.

**exporting-markdown-diagrams 옵션**

- **FR-018**: 설정은 문서 전체 PDF의 레이아웃 기본값을 "매번 묻기", "1페이지 단일", "표준 인쇄 규격" 중에서 고를 수 있어야 한다(기본: 매번 묻기). "매번 묻기"가 아니면, 요청이 레이아웃을 밝히지 않았을 때 묻지 않고 설정된 레이아웃을 쓴다.
- **FR-019**: 설정은 PNG 해상도 배율을 양수로 정할 수 있어야 한다(기본: 3).
- **FR-020**: 설정은 산출물이 모이는 하위 폴더 이름을 정할 수 있어야 한다(기본: `exports`). 이름은 원본 파일과 같은 디렉터리 아래 한 단계 폴더 이름으로만 해석하며, 경로 구분자나 상위 디렉터리 이동이 들어 있으면 허용되지 않는 값으로 보고 FR-005를 따른다.
- **FR-021**: 설정은 문서 전체 PDF에서 접은 글 박스를 펼친 상태로 담을지 켜고 끌 수 있어야 한다(기본: 켬). 켜면 PDF 안의 모든 접은 박스가 펼쳐진 상태로 담겨 내용이 빠짐없이 보이고, 끄면 원본처럼 접힌 상태로 담긴다. 원본 마크다운 파일은 어느 쪽이든 바뀌지 않는다.
- **FR-022**: 이 스킬의 설정 값은 번들 스크립트가 직접 읽어 적용해야 한다. 변환 결과가 LLM 판단에 의존하지 않는다는 기존 원칙(004 spec)은 그대로 유지된다. 레이아웃 질문을 생략할지 같은 대화 흐름 판단만 SKILL.md가 설정을 읽어 결정한다.

### Key Entities *(include if feature involves data)*

- **스킬 설정 파일**: 스킬마다 하나씩 그 스킬 디렉터리 안에 있는 JSON 문서. 사용자가 직접 편집하며, 처음부터 모든 옵션이 기본값으로 적혀 있다. 키마다 허용 값과 기본값이 정해져 있다.
- **설정 옵션**: 키 이름, 허용 값(켬/끔, 정해진 선택지, 양수, 폴더 이름), 기본값(= 기능 도입 전 동작)으로 이뤄진다. 위 FR-008~FR-021이 스킬별 옵션 목록이다.
- **설정 안내**: 설정 파일을 읽지 못했거나 일부 값을 기본값으로 대체·무시했을 때 채팅 응답에만 붙는 한 줄. 대상 파일과 키를 밝힌다.
- **접은 글 박스**: 마크다운 미리보기에서 기본으로 접혀 있고 클릭해 펼칠 수 있는 블록. 요약 줄과 접힌 내용으로 이뤄진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 설정 파일을 건드리지 않은 상태에서 세 스킬의 산출물이 이 기능 도입 전과 달라지는 비율이 0%다(대표 테스트 시나리오 기준).
- **SC-002**: 각 옵션을 기본값과 반대로 바꿨을 때, 그 옵션에 해당하는 부분만 달라지고 나머지 산출물은 같은 비율이 100%다(옵션별 대표 시나리오 기준).
- **SC-003**: 사용자가 설정 파일 하나만 열어 원하는 옵션을 찾아 바꾸고 다음 실행에 반영되기까지, 다른 문서를 찾아보지 않아도 되는 비율이 100%다(설정 파일 안에 모든 옵션과 기본값이 이미 적혀 있음).
- **SC-004**: 읽을 수 없는 설정 파일, 잘못된 값, 알 수 없는 키가 있는 상황에서 작업이 중단되는 비율이 0%이고, 그 사실이 채팅에 한 줄로 안내되는 비율이 100%다.
- **SC-005**: 접은 글 펼치기가 켜진 상태에서 접은 박스가 있는 마크다운 파일을 문서 전체 PDF로 내보냈을 때, 접힌 내용이 PDF에서 빠지는 비율이 0%다.
- **SC-006**: 같은 설정과 같은 입력 파일로 내보내기를 반복했을 때 결과물의 형식(레이아웃, PNG 픽셀 크기, 산출 폴더, 접은 박스 상태)이 매번 같은 비율이 100%다.

## Assumptions

- **설정 파일 위치**: 각 스킬 디렉터리 안에 둔다. 스킬을 다른 프로젝트에 복사해 쓰면 설정도 함께 따라간다. 저장소에서는 기본값이 적힌 상태로 추적된다.
- **접은 글 박스의 형식**: 마크다운 미리보기(VS Code 기본 미리보기, GitHub)가 기본으로 접힌 상태로 렌더링하는 표준 HTML 접기 블록을 쓴다. 박스 안의 마크다운과 Mermaid 다이어그램이 펼쳤을 때 정상 렌더링되도록 형식을 맞추는 것은 계획 단계에서 실측으로 확정한다.
- **Dependency는 접기 대상에서 제외**: 사용자가 Responsibility와 Collaboration만 언급했고, Dependency는 구조 뷰를 펼쳤을 때 가장 먼저 보여야 할 내용이므로 옵션을 두지 않는다.
- **zenuml 옵션 선정 기준**: 이 스킬이 이미 내리는 판단 중 사람마다 선호가 갈릴 수 있는 것(종류 표시, 주석, 지어낸 이름의 언어, 로그)과 사용자가 직접 언급한 접기만 옵션으로 뽑았다. 다이어그램 제목처럼 번들 문법 레퍼런스에 없는 문법이 필요한 옵션은 넣지 않는다.
- **exporting 옵션 선정 기준**: 지금 스크립트에 고정돼 있거나(PNG 배율, 산출 폴더 이름) 매번 묻는 것(PDF 레이아웃)과, 접은 글 도입으로 새로 필요해진 PDF 펼침 여부만 옵션으로 뽑았다. 형식·범위 질문은 요청마다 달라지는 값이므로 설정으로 고정하지 않는다.
- **우선순위**: 요청 문장 > 설정 파일 > 기본값. 요청 문장의 지정은 그 요청에만 적용되고 저장되지 않는다(003 FR-007b의 렌더러 지정과 같은 원칙).
- **로컬 개인 기본값과의 관계**: CLAUDE.local.md에 둔 렌더러 기본값 같은 개인 지침은 이 설정 파일과 별개로 유지되며, 이 기능이 대체하지 않는다.
